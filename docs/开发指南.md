# 开发指南

本文维护开发、验证、排障和安装操作；实现契约见[工程结构](工程结构.md)，Agent／脚本用法见[挑战初始化桥接接口](挑战初始化桥接接口.md)，前端局部约定见 [WebView README](../webview/README.md)。版本变化查 [CHANGELOG](../CHANGELOG.md)，不在这里逐次追加实施过程和测试结果。

## 环境与导入

使用 JDK 25、Node.js 24 和仓库自带的 Gradle Wrapper。将 `JAVA_HOME` 指向 JDK 25，确保 `java`、`node`、`npm` 可用；在 IDEA 中打开仓库并加载 Gradle 工程，Gradle JVM 同样选择 JDK 25。

目标 IDEA 及最低构建号以 `gradle.properties` 的 `platformVersion`／`platformSinceBuild` 为准；Gradle 与 npm 依赖分别由 Wrapper 和 `webview/package-lock.json` 固定。Kotlin 运行库复用目标 IDE。不要恢复 SBT、Scala、UI Designer 表单或本地数据库构建链。

## 构建与检查

从仓库根目录执行：

```bash
# 编译、离线业务回归、前端检查、插件打包及工程配置检查
./gradlew check buildPlugin verifyPluginProjectConfiguration

# 启动独立沙箱 IDE
./gradlew runIde

# 平台 API 兼容性检查，可能需要下载验证器与目标 IDE
./gradlew verifyPlugin

# 单独构建前端／检查已退休依赖未重新打包
./gradlew buildWebview
./gradlew verifyRuntimeLibraries
```

默认业务测试不访问真实力扣服务，不意味着首次构建无需联网下载依赖。需要复用本地 IDEA、且 Gradle 依赖已缓存时：

```bash
JAVA_HOME="$HOME/Applications/IntelliJ IDEA.app/Contents/jbr/Contents/Home" \
  ./gradlew check buildPlugin verifyPluginProjectConfiguration --offline \
  -PlocalPlatformPath="$HOME/Applications/IntelliJ IDEA.app"
```

确认该目录是目标版本，不把本机绝对路径写入构建配置。`--offline` 限制 Gradle 依赖解析，不能替代 npm 缓存或离线准备；Plugin Verifier 离线运行也要求相关依赖已缓存。排除任务复用时加 `--rerun-tasks`；`clean` 仅清理输出，仍可能命中构建缓存。

报告位于 `build/reports/tests/test/`、`build/test-results/test/` 和 `build/reports/pluginVerifier/`；安装包位于 `build/distributions/`。检查、打包和 Verifier 均按上述命令在本地执行。

## 测试与验收

按变更选择下表中的回归，最后执行完整检查。测试数量不是覆盖结论；编译、测试、打包、API 兼容、安装文件校验和真实客户端验收分别报告。修改目标平台、依赖、平台 API 或扩展注册时另行执行 `verifyPlugin`，检查兼容错误及废弃／待移除 API 报告；默认完整检查不包含它，未执行或受环境阻塞时须明确说明。

| 变更领域 | 主要测试入口 | 必须区分的边界 |
|---|---|---|
| 识别与提交区域 | `ChallengeRecognitionTest`、`SourceRegionsTest`、`ExecutionRequestTest` | 真实注释／字符串、唯一边界、未保存快照、后台 questionId；不等于真实 Document／保存事件验收 |
| 骨架、另存与工程 | `JavaTemplateStubTest`、`GoTemplateStubTest`、`GeneratedSkeletonFormattingTest`、`GeneratedChallengeFileTest`、`DefaultLanguageSettingsTest`、`LanguageProjectInitializationTest` | 平台签名、Java 8 编译、Go 正文、非法名称、不覆盖及已有工程复用；不操作真实另存对话框 |
| 初始化与桥接 | `ChallengeInitializationTest`、`ChallengeBridgeServerTest`、Node 客户端测试 | 旧 XML 不读取且字节不变，created／already_exists／conflict／partial，鉴权、并发和取消；不执行真实提交 |
| 认证与 HTTP | `AuthenticationSessionTest`、`CookieStoreTest`、`HttpTlsTest`、`LeetCodeClientTest` | 协调、取消、协议和 TLS；不等于真实 PasswordSafe、代理、登录会话验收 |
| 搜索与查询 | `ProblemFilterPipelineTest`、`ProblemSearchBarTest`、`LatestQueryTest`、`ArticlePreviewSelectionTest` | 生产菜单／请求链、慢消费者及列表—预览失效；mock 返回不证明远端已执行筛选 |
| 编辑器与注册 | `ChallengeEditorContextTest`、`ChallengeEditorTitlesServiceTest`、`DelegatingTextEditorTest`、`PluginDescriptorTest` | 动作上下文、标题服务启用门禁和刷新、事件桥接、DumbAware、实际 JAR／全部 GraphQL 资源及折叠注册；不等于完整 editor composite／JCEF 验收 |
| API 与退休契约 | `ArticleAndChallengeResponseTest`、`QueryRetirementTest` | 最小响应、会员列表字段、无用 serializer／组件退出产物；拦截器 fixture 不证明真实站点 schema |
| 提交信息交付 | `SubmissionConsoleTest`、`ExecutionMessageTest` | 真实测试应用 EDT 的取消／释放与标题格式；不等于完整项目关闭或平台提交 |
| WebView | `WebResourcesTest`、`webview/plugin/runtime.test.mjs` | CSP／编码与真实运行时源码；DOM／滚动条替身不证明真实 JCEF 布局和加载时序 |

定向执行示例：

```bash
./gradlew test --rerun-tasks \
  --tests 'io.github.yungyu16.algostack.presentation.LatestQueryTest' \
  --tests 'io.github.yungyu16.algostack.presentation.SubmissionConsoleTest' \
  --tests 'io.github.yungyu16.algostack.execution.ExecutionMessageTest'
```

TLS 测试通过 JDK `keytool` 在临时目录生成证书，用回环 HTTPS 验证证书与主机名校验，私钥不提交。Java 模板测试使用 `javac --release 8`；Maven 测试只解析 POM，不以下载 Maven 插件作为验收。需要本机 Go 实际检查生成工程时设置 `ALGOSTACK_VERIFY_GO=true`；测试使用 `GOPROXY=off`、`GOSUMDB=off`、`GOTOOLCHAIN=local`、`GOWORK=off`，不下载依赖。默认测试注入 Go 版本值，不要求安装 Go。

### 真实 IDEA 验收清单

以下是按风险选择的检查项，不是已通过结论。使用可丢弃的标记项目；真实登录、测试／提交、安装和卸载须在用户授权范围内执行，不读取钥匙串或导出 Cookie 代替授权。

| 场景 | 检查内容 |
|---|---|
| 激活与认证 | `.leetcode` 文件／目录均启用，无标记不显示业务窗口、不恢复凭据或启动桥接；保存会话静默恢复失败不弹窗，手动 Login 可用，多项目共享中国站会话 |
| 新题与旧文件 | Java/Go 首次生成、重复初始化、重名另存、非法输入和取消；题面含其他题目链接时按 `@leetcode` 主身份识别，非法/重复声明拒绝，无声明文件按普通 URL 规则识别；原文件、旧 XML 与工程描述文件不变，无项目状态 XML 新增；移动、改名及未保存内容仍按源码识别 |
| 搜索与筛选 | 输入草稿不查询，Enter／按钮提交；筛选、排序、分页使用已提交关键词；切范围保留条件并回首页，公司未选时不查；对比实际请求和平台结果 |
| 查询与侧边栏 | 快速切题／选文章／重复查询，翻页／筛选时取消旧详情，清空选择后正文清空；旧成功或错误不覆盖新上下文，同内容新结果仍能显示；非题目隐藏 Description/Solutions，工具窗口焦点不切编辑器。难以手工命中的排队窗口由确定性测试补充 |
| 编辑器 | 索引期间打开题目／预览；中文标题、身份切换及关闭重开正常，未启用项目不激活标题服务；选区动作、悬浮工具栏、提交区域折叠、加载就绪、编辑保存后的图标、文件失效及关闭正常。Surround region 不是运行按钮，已有提交区域不得重复包围 |
| 测试与提交 | 多参数默认用例输入和失败输出对应；平台失败不伪装成功；受理后取消不撤回远端，项目仍打开时保留已交付 ID／链接，先核对平台结果再决定是否重试 |

## 筛选诊断

先区分输入草稿、已提交条件、请求快照和服务端结果。`ProblemFilterPipelineTest` 经过生产筛选 host、菜单动作、请求加载器和回环 HTTP，但不完整装配题库视图、认证与真实工具栏弹窗。

IDEA 日志中的 `problem_query` 事件可辅助定位：

- `filter`：mode、kind、optionId、selected。
- `load`／`loaded`／`applied`：mode、page、count、total，其中 load 的 count 是页容量。
- 每类事件两秒最多一条，后续附 suppressed 数量；不记录关键词、账号、凭据、代码或响应正文。

日志不是逐动作审计。先判断动作是否改变状态、请求是否发出、结果是否应用，再核对远端语义；不能仅凭题目数相同判断筛选失效，也不凭 mock 样例猜测平台协议已变化。

## 网络与调试

HTTP 使用正常证书链和主机名校验及 IDEA 代理配置。组织代理／自签名证书应配置进运行 IDEA 的 JVM 信任库，不跳过 TLS 校验。

Gradle JVM 不匹配时检查 `JAVA_HOME`，它与编译 toolchain 是不同入口。Shell 可执行 npm 但 daemon 找不到时，可用 `--no-daemon` 排除旧进程环境；不要把个人绝对路径写入仓库。`runIde` 首次启动可能需下载调试组件，离线前先准备缓存。

测试或 ActionSystem 初始化失败时先检查堆栈是否进入业务断言，区分平台缓存／环境失败与业务失败；不通过跳过断言、直接删缓存或重新打包冒充修复。历史日志和构建目录会被覆盖，不能用于反推另一批次结果。

## WebView 类型检查与运行时回归

从 `webview/` 执行 `npm run check`（类型检查与运行时测试）、`npm run build`（Vite 打包）。Gradle `checkWebview` 和 `buildWebview` 分别调用这两项。共享 runtime 的源码、全局接口及主题注入只在 [WebView README](../webview/README.md) 维护。

检查产物时追踪两页入口到共享 chunk、CSS 和字体的依赖。`intellijStyle.css` 由 Kotlin 动态提供，不要求它是静态文件；不要凭压缩后的第三方函数原名判断模块丢失。真实 JCEF 效果按上方清单验收。

## 本机安装与回滚

构建包、磁盘已安装插件、正在运行的 IDEA 可能是不同版本，不能由源码 `pluginVersion` 推断当前运行态。安装和构建分开报告：

1. 获得授权并确认目标 IDEA 完全退出，不强制结束用户进程。固定源码提交和工作区范围；并行修改时核对构建前后输入一致。
2. 完整验证并打包，从 ZIP 内主 JAR 的 `META-INF/plugin.xml` 核对 ID、版本和依赖，记录 ZIP／主 JAR SHA-256，不只看文件名。
3. 备份完整旧插件目录，再从 ZIP 整体替换；逐文件核对安装树，避免混入旧运行库，不只覆盖主 JAR。
4. 安装清单与备份放在同一个本机目录，记录源码范围、产物哈希、安装／备份位置、校验结果和未完成验收。已有本机记录位于 `~/Library/Application Support/AlgoStack-backups/`；以实际 manifest 和文件为准，不在仓库按安装次数复制报告，也不把版本或备份永久视为有效。
5. 不改刷题项目、PasswordSafe 或 Cookie；不自动启动 IDEA。重启后按变更范围验证客户端行为。

回滚须先退出 IDEA，恢复完整旧插件目录，不混用两版 JAR。备份不存在或校验不符时，不声称仍可回滚。需要合规、对外交付或用户明确要求的发布证据时，再按约定单独留存。

## 发布与 Marketplace 上传

版本以 `gradle.properties` 的 `pluginVersion` 为准，每个交付版本一个 annotated tag（`v<version>`，如 `v1.0.22`），tag 指向该版本交付提交。发布由 `.github/workflows/publish.yaml` 执行：推送 `v*` tag 触发构建、上传 JetBrains Marketplace（`xmlId=io.github.yungyu16.algostack`）并创建 GitHub Release；`workflow_dispatch` 手动触发仅构建不发布。工作流校验 tag 版本与 `pluginVersion` 一致，不一致直接失败。

1. 发布前在仓库 Settings → Secrets 配置 `JETBRAINS_TOKEN`（JetBrains 账号在 plugins.jetbrains.com 生成的永久 token）；token 缺失或无效时上传步骤失败，不影响构建产物。
2. 推送顺序：先推送 main（历史重写后需 `--force-with-lease`），再推送目标 tag；只推需要上架的版本 tag，每个 `v*` tag 推送都会触发一次上传。
3. 新插件首次上传会创建 Marketplace 条目并进入人工审核；审核通过前列表页不可见，上传失败或审核意见以 Marketplace 作者后台为准。
4. 本机磁盘安装与 Marketplace 安装是两条更新链：磁盘安装不会被商店更新覆盖，切换安装来源需卸载后从商店重装。
5. 列表页元数据分两套来源：`plugin.xml`（`<description>`、`<change-notes>`、图标、兼容性）随包上传，与 Marketplace 作者后台的“Preserve changes from UI”开关共同决定最终展示。当前值为 **Use changes from UI**：描述、Getting Started、Contacts 等字段以后台编辑为准，发新版本不会用包内 `plugin.xml` 的描述覆盖后合修改。

   因此描述类文案存在两份：仓库 `plugin.xml` 的一份随包分发（也是 IDE 插件管理页与离线场景的来源），后合的一份是列表页展示的实际来源。**改文案时两边同步**，否则两者会不一致；只改后合无需发版，只改 `plugin.xml` 需发新版本且在后合为 `Use data from plugin.xml` 时才生效。插件名称、ID、许可证、兼容性始终以 `plugin.xml` 为准，不受该开关影响。

## 维护与交付

变更前核对当前调用链和工作区，行为修复尽量先补可失败的回归。评审优先关注文件／提交安全、状态交接和资源释放；有证据的缺陷、维护成本和待验证风险分别说明，不因代码长或有重复就重构。每项治理应关联具体场景、修复提交和验证结果，不额外生成通用方法论或临时实施方案作为项目文档。

项目说明按职责更新：操作写本文，实现与兼容契约写[工程结构](工程结构.md)，外部协议写[桥接接口](挑战初始化桥接接口.md)。版本变化进入 CHANGELOG；一次性执行结果通过当次交付或本机安装清单追踪。提交、版本和授权边界遵循 [AGENTS.md](../AGENTS.md) 与[参与维护](../CONTRIBUTING.md)。
