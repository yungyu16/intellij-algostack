# 开发指南

## 环境与导入

使用 JDK 25 和 Node.js 24。Gradle 版本由 Wrapper 固定，npm 依赖由 `webview/package-lock.json` 固定。将 `JAVA_HOME` 指向 JDK 25，确保 `java`、`node` 和 `npm` 可用。

在 IDEA 中打开根目录并加载 Gradle 工程，设置 Gradle JVM 为 JDK 25。业务、IDE 集成与 Swing UI 均使用 Kotlin，不维护 Java UI Designer 表单或表单专用插桩配置；IntelliJ Platform Gradle Plugin 的标准字节码处理仍保留。Kotlin 运行库复用目标 IDE；开发和运行均不再要求 Scala 插件或 Scala 运行库。

`.editorconfig` 统一基础格式。`.kotlin/` 会话目录与其他构建缓存一起忽略。

## 常用命令

从仓库根目录执行：

```bash
# 编译、执行离线测试并生成插件 ZIP
./gradlew check buildPlugin

# 启动独立沙箱 IDE 调试
./gradlew runIde

# 检查插件工程配置
./gradlew verifyPluginProjectConfiguration

# 检查平台 API 兼容性（需要下载验证器与目标 IDE）
./gradlew verifyPlugin

# 仅构建前端
./gradlew buildWebview

# 检查运行时没有重新引入已移除的依赖栈
./gradlew verifyRuntimeLibraries
```

默认目标版本由 `gradle.properties` 的 `platformVersion` 决定，当前为 IDEA 2026.2.3；`platformSinceBuild` 限定最低平台构建号。修改后需要真实构建、API 兼容检查及客户端验收，不能仅改版本号宣布兼容。

需要复用本地 IDEA 以免重复下载时：

```bash
JAVA_HOME="$HOME/Applications/IntelliJ IDEA.app/Contents/jbr/Contents/Home" \
  ./gradlew check buildPlugin verifyPluginProjectConfiguration --offline \
  -PlocalPlatformPath="$HOME/Applications/IntelliJ IDEA.app"
```

本地平台路径只通过命令参数或个人 Gradle 配置提供，不写入仓库。切换目标版本时，确保该路径指向对应版本。

网络受限且构建依赖已缓存时，可以执行离线兼容性检查。Gradle 的 `--offline` 会同时传给 Plugin Verifier，使其仅解析本地已下载的插件依赖；未缓存的依赖仍会导致检查无法完成。

```bash
./gradlew verifyPlugin --offline -PlocalPlatformPath="/path/to/IntelliJ IDEA.app"
```


## 本机安装与回滚

安装与构建分开报告。`buildPlugin` 生成 ZIP 不代表已安装；复制文件成功不代表真实 IDEA 交互已通过。源码工作区版本、安装包版本和已安装版本也可能不同，不用当前 `pluginVersion` 推断用户正在运行的版本。

1. 确认目标 IDEA 进程完全退出，明确实际插件目录；不强制结束用户进程。
2. 固定本次源码范围，记录提交及工作区状态，再执行完整检查和打包。有并行改动时检查构建前后源码是否一致；未通过完整测试的包不得描述成验证通过。
3. 从 ZIP 内主 JAR 的 `META-INF/plugin.xml` 核对插件 ID、版本与平台依赖，记录 ZIP 和主 JAR 的 SHA-256。不要仅凭文件名判断版本，也不要将未提交的工作区包描述成某个纯提交产物。
4. 备份完整已安装插件目录，再从 ZIP 整体替换，不只覆盖主 JAR；安装后核对整个文件树与包内文件一致，避免残留旧版本运行库。
5. 在本机备份旁记录安装清单：源码范围、版本、产物哈希、安装位置、旧版位置和校验结果。长期项目记录放在对应版本的文档中，不反复追加到 `1.0.0` 历史记录；后续构建可能覆盖同名 ZIP，哈希必须与当次产物对应。
6. 不改动刷题项目、旧 XML、历史数据库、PasswordSafe 或 Cookie；除非用户要求，不自动启动 IDEA。重启后再按改动范围进行客户端验收。

回滚时先退出 IDEA，恢复备份里的**完整插件目录**，不要混用两版 JAR；插件程序回滚不包含题解、项目配置或历史数据库回滚。已删除的旧插件副本不能继续视为可用回滚点。

[1.0.4 验证与安装记录](1.0.4验证与安装记录.md)记录了该次已完成的安装及尚未确认的 UI 行为，不代表当前源码或未来版本的安装结果。

## 测试与验收

默认测试不调用真实力扣服务。已移除依赖个人 Cookie、固定本机代理和打印远端响应的手工 API 脚本。Kotlin JUnit 测试由 Gradle 的 `test` 执行；测试报告在 `build/reports/tests/test/`。

TLS 测试用 JDK 自带的 `keytool` 在临时目录生成证书，启动回环地址 HTTPS 服务，验证拒绝不可信证书，以及显式信任证书后仍检查主机名。私钥不检入仓库，测试结束后删除。协议测试使用本地响应替身。

回归覆盖内置模板、旧 XML 不参与初始化且不改写、Java/Go 内容身份识别正反例（含 URL 在头部、package/import 后、类/方法注释中语义一致，BOM/换行、字符串排除、跨题冲突与唯一区域）、语言版本与提交区域契约、初始化不覆盖/冲突/部分失败/取消、Java 8 Maven 与 Go module 首次生成和幂等、单语言创建、自定义路径及已有工程保护、目录重命名、查询取消、文件/目录标记与无标记零业务启动、启动/多视图共享认证、静默失败去重及手动回退/取消重试、标签页策略、插件无数据库依赖及 WebView 内容策略。不再维护数据库、笔记与提交历史 VFS 测试。插件描述符检查既验证类可加载，也验证自定义动作引用位于注册之后。这些检查不等于完整 IDEA 交互验收。

需要额外用本机 Go 校验实际生成的 `go.mod` 和两个独立题目包时，可在完整验证命令前设置 `ALGOSTACK_VERIFY_GO=true`。默认测试注入版本值，不要求安装 Go；显式检查设置 `GOPROXY=off`、`GOSUMDB=off`、`GOTOOLCHAIN=local`、`GOWORK=off`，执行 `go mod edit -json` 和 `go test ./...`，不下载依赖。Maven 测试只解析生成的 POM 并验证 Java 8 属性，默认模板另用 `javac --release 8` 验证；不以联网下载 Maven 插件作为验收。

构建成功只证明代码与打包流程通过。安装后还需人工检查：中国站题目入口和 Java／Go 语言选择、国际站显式请求拒绝、Login 对话框与浏览器页面、拉题、模板生成、测试、提交、Console 结果及平台题解。使用测试账号和可丢弃的沙箱项目，真实提交由使用者自行执行。

当前回归覆盖无 URL 拒绝、AnyVersion 内容身份、初始化 already_exists/conflict 与旧 XML 不参与业务；URL query/fragment/子页与 Markdown 括号及末尾标点，以及 Java 文本块/Go raw string/块注释中的伪区域均有离线测试；伪标记在真实区域前、区域内及区域后均不会改变实际提取字节。扩展名唯一时的身份识别、歧义扩展名拒绝、全语言区域提取和缺失、倒序、重复、嵌套区域拒绝有枚举回归。只读核对的旧 Go 文件形状为 `package main` → 题面块注释（含 URL）→ 标准提交区域；测试仅存最小骨架，不依赖个人绝对路径。Java/Go 区域检查只跳过常见字面量与注释，不构成完整语言语法或可编译性验证。

1.16.1 的识别回归来自只读核对的旧 Java 文件形状（`package leetcodecn;` → 题面块注释 → 外层类及标准提交区域），测试只保存最小骨架，不复制用户题解、不依赖个人绝对路径。新增 Java/Go 用例先在旧实现失败，再于修复后通过；这只验证识别根因与标签页策略，不代表已安装插件的 UI 已通过验收。当前版本已取消 Java/Go 头部位置限制，支持边界见[工程结构](工程结构.md#题目身份与旧文件)。

内容快照回归验证未保存文本改变 URL/代码后重新识别与提取、缺 URL 拒绝及恢复原文时重新识别；未改动 `resolve(VirtualFile)` 的 cached Document 优先/VFS 回退、`SidebarContext` 的 read action/取消发布和执行前 `saveAndRead` 后身份复核。该测试不装配真实 Document、保存动作或 IDE 事件，仍须人工验收。

客户端验收还应检查：无设置页，旧语言/模板配置不影响固定约定；筛选分页恢复默认；无标记时整个窗口与题目编辑器增强不出现、不读凭据或启动桥接，文件/目录标记均有效；标记项目不点题库 tab 即恢复已保存登录态，无凭据/失效不弹窗，手动 Login 可用，多项目/视图不重复恢复；旧 Java/Go 内容识别（特别是 package 在题面注释前，安装 1.16.1 后应出现 Description/Solutions）；未保存内容修改能重新识别、没有 cached Document 时 VFS 读取正常且不报线程访问异常；非题目隐藏 Description/Solutions 而保留题库和 Console，仅切换工具窗口 tab 不误清题目、不切换编辑器、不重复加载相同身份；快速切换题目/筛选时旧响应不覆盖新结果；关闭视图或项目后请求停止；不恢复国际站凭据；中国站跨项目登录状态一致。默认用例与项目无状态的自动检查及人工验收见下节。

搜索交互验收：默认 Console / Problems；首行范围下拉、输入与搜索按钮在短窗口仍可操作；输入不发请求，Enter 与按钮一致；已提交关键词与分类/题单、难度、状态和标签组合生效；输入新草稿后筛选、排序与翻页不发送草稿，点击搜索才回首页并提交；切换范围保留各自字段/草稿并重置分页、排序。公司范围未选公司时保持空结果，不伪装为全部题目。

CI 在推送和 Pull Request 时运行 `check buildPlugin verifyPluginProjectConfiguration`，上传 ZIP 及测试报告。手动运行 Build workflow 时还执行 `verifyPlugin` 并上传 `build/reports/pluginVerifier/`。修改目标平台或依赖后应执行这一检查；查看结论时同时关注兼容错误、待移除、废弃和实验性 API 报告。不自动发布到 JetBrains Marketplace。

## 编辑器工具栏上下文

悬浮工具栏与文本编辑器位于同一个 `JBLayeredPane` 下，是兄弟组件，不能从编辑器子树继承 `CommonDataKeys.EDITOR`。公共容器通过 `UiDataProvider` 显式提供当前 Project、VirtualFile、底层 Editor 和包装后的 FileEditor，避免依赖全局焦点或当前窗口猜测。

`SurroundSubmissionRegionAction` 要求题目编辑器状态存在且有非空选区。`ChallengeEditorContextTest` 在测试应用 EDT 中构建真实包装容器和工具栏，使用替身 Editor／TextEditor 读取公共容器的上下文快照，验证对象绑定一致、无选区禁用以及有选区启用；修复前缺少公共快照时失败，修复后通过。测试没有在真实 IDEA 窗口中操作鼠标选区，安装后仍需确认悬浮工具栏和右键入口表现。

内置模板已包含提交区域，正常刷题无需使用 Surround region；当前动作不会检查已有标记，不应在已有区域中再次包围，以免产生重复或嵌套标记。

## 默认用例与无项目状态

项目级题目关联和自定义用例功能已移除。识别只依赖源文件内容，运行测试只使用本次平台响应的 `exampleTestcaseList`；平台失败时报告错误，不回退旧 XML 或快照。`associated` 是桥接 v1 保留字段，仅表示源码身份核验，不表示写入项目状态。

定向回归：

```bash
./gradlew test \
  --tests 'io.github.yungyu16.algostack.execution.ExecutionRequestTest' \
  --tests 'io.github.yungyu16.algostack.execution.ChallengeInitializationTest' \
  --tests 'io.github.yungyu16.algostack.domain.ChallengeRecognitionTest' \
  --tests 'io.github.yungyu16.algostack.model.PluginDescriptorTest'
```

默认用例请求回归检查后台 questionId、每次平台响应的新输入、多参数用例边界及身份冲突拒绝；初始化回归检查不创建 `.idea`、旧非法 XML 不影响内容判断或新文件生成且字节不变、重复初始化不覆盖、失败保留骨架和取消传播。产物回归检查自定义用例动作、弹窗、持久化服务与路径监听均已移除，测试／提交入口仍存在。

定向测试不能替代完整的 `check buildPlugin verifyPluginProjectConfiguration`。排除任务缓存时使用 `--rerun-tasks`；`clean` 只清理输出，仍可能命中 Gradle 构建缓存。测试不调用真实力扣站点，不能证明实际平台执行通过。

安装到可丢弃的标记项目后，还需人工检查：

- 文件工具栏和右键菜单没有自定义用例按钮，正常测试／提交入口仍在。
- 没有 `challenge.xml` 时，Java／Go 题目生成、识别、Description／Solutions 和默认用例测试可用；操作后不新增项目题目状态 XML。
- 保留旧 XML 的项目不恢复自定义用例、不改写文件；移动、重命名及未保存源码修改后仍按当前内容识别。
- 多参数默认用例在失败输出中按用例完整显示；平台失败报告错误，不伪装成功。
- 真实测试或提交须经用户授权；本地回归不执行真实提交。

## 筛选诊断

1.17.2 排查未在离线条件下复现“label 筛选不生效”，不宣称修复了服务端或真实弹窗问题。源码核对确认：弹窗 CheckboxAction 捕获实际 host，setSelected 与当前选择不同时调用 toggle；视图 parameters/company setter 写回同一个 ProblemQueryState，未发现委托属性丢弃。为直接测试生产逻辑，将原有选项／切换方法原样提取为 ProblemFilters，仍与视图共享唯一 state；不可变 ProblemPageRequest 负责原有加载分派，不新增持久化或平行状态。

ProblemFilterPipelineTest 初始化测试 ActionSystem，在 EDT 构造实际 FilterAction 菜单并调用 actionPerformed/setSelected（执行事件不含 FILTERS，验证捕获 host），通过生产 host 修改条件，使用生产请求快照／加载器、LatestQuery 和回环 HTTP mock 验证 GraphQL 请求体、取消参数及解析结果。普通题库分类是 variables.categorySlug、题单是 filters.listId、标签是 filters.tags；取消分类回到 all-code-essentials，取消题单／标签不再发送对应字段。公司范围不发送普通分类／题单，通过 favoriteSlug 表达首个公司与时间范围，其他公司、职位、难度、状态、标签进入 filtersV2；没有公司不发查询。状态值按现有契约序列化，不猜测远端 API 已改变。

该回归用 Swing EDT 测试表格接收 mock 结果，**未装配完整 ChallengesView、认证服务、真实工具栏弹窗和平台 EDT 调度器**；视图对 ready、当前快照与关闭状态的判断仅经源码核对，快速替换／取消保护另由 LatestQueryTest 验证。没有真实账号或远端响应证据，不能把 mock 返回的固定题目说成服务端已按筛选生效。仍须在用户允许的登录会话中检查实际弹窗选择、请求及结果，尤其是需要登录的状态／个人题单；不读取钥匙串或导出 Cookie 来复现。

实际视图在 IDEA 日志输出 problem_query 结构化事件：filter 包含 mode、kind、optionId、selected；load／loaded／applied 包含 mode、page、count、total（load 的 count 为请求页容量）。每类事件两秒最多一条，后续事件附 suppressed 数量；快速点击可能被采样，日志不是逐动作审计。标识截断并过滤控制字符，不记录关键词、账号、凭据、代码或响应正文。原查询异常原因仍由原有日志保留；没有增加网络轮询或重试。可据此区分动作未修改条件、未加载、加载失败和结果未应用，不据题目数相同就认定筛选无效。

## 查询结果与受理信息交付

`LatestQueryTest` 使用真实 StateFlow collector 暂停旧终态消费，让同内容的新请求完成后再恢复，验证旧状态被拒绝、新状态仍会交付；成功和复用同一异常的失败均覆盖。终态实例本身就是请求标识，不按业务内容去重。测试不装配完整题解面板，切题／筛选交互仍需真实 IDEA 验收。

`SubmissionConsoleTest` 在测试应用中阻塞真实 EDT，调用生产 Console 受理输出后取消任务，验证提交 ID 和超链接各输出一次、取消后不继续执行；另在恢复 EDT 时先调用 Console 的 dispose，验证已释放时跳过排队输出。它不执行真实提交、不打开链接，也不等于完整项目关闭或插件卸载验收。`ExecutionMessageTest` 验证进度与 Console 共用的格式化函数不留下未替换参数。

## 网络与调试

HTTP 客户端使用正常的证书链和主机名校验，并读取 IDEA 的代理配置。使用组织代理或自签名证书时，将受信任的证书配置到运行 IDEA 的 JVM 信任库；不要用跳过校验的代码绕过错误。普通直连、代理和浏览器登录仍需在实际环境中验证。

`runIde` 首次启动可能需要下载 Gradle 插件的调试运行组件；离线运行前需先缓存相关依赖。开发时的运行组件不等于安装包中的运行库。

若 Gradle 报 JVM 版本错误，先核对启动 Gradle 的 `JAVA_HOME`，它与编译 toolchain 是不同的入口。若 Shell 中 `npm` 可用但已有 Gradle daemon 无法启动它，可用 `--no-daemon` 做一次验证，排除旧进程环境的影响，不把本机绝对路径写入构建脚本。

## 内置生成约定与无数据库边界

生成规则由 `execution/ChallengeConventions.kt` 和 `src/main/resources/templates/leetcodecn/` 的内置模板维护，不读取旧语言、路径、模板及 CSS 配置。设置页、模板编辑器及 JFlex／Grammar-Kit 构建环节已移除。

Java 新骨架在 `ChallengeTemplate.getCode()` 中通过 `JavaTemplateStub` 补齐空方法：使用 IDEA 内置 Java PSI 区分方法、构造器、注释与字符串，仅给空的非构造方法加入 `throw new UnsupportedOperationException("Not implemented");`。不改方法签名或已有实现，不给抽象方法、构造器填充异常；Go 仍透传平台骨架，不改已有题目文件。插件声明 `com.intellij.java` 依赖，生成时在 read action 中解析临时 PSI，不保存源码或项目状态。

手动重名另存由 `saveNewFile` 先确定最终路径，再调用 `PreparedChallenge.codeForFile` 取得正文。`execution/GeneratedChallengeFile.kt` 使用临时 Java PSI 定位原文件名对应的顶层 `public` 类，只替换声明标识符，并检查提交区域提取结果前后相同；不是全局字符串替换，不读取或改写已有源码。文件名校验拒绝 Java 关键字、受限类名及非法标识符；实际写入仍使用 `CREATE_NEW` 防止同名覆盖。

修改生成规则后执行 `JavaTemplateStubTest`、`GeneratedChallengeFileTest`、默认模板、Java／Go 工程初始化及插件产物回归，检查空方法、泛型／数组／void／throws 签名、注释和字符串不误改、重复处理幂等、Java 8 编译、唯一提交区域与不覆盖保护。`GeneratedChallengeFileTest` 覆盖合法／非法名称、外层类与文件名一致、平台区域及原文件不变、拒绝改写区域内平台类和 Go 正文透传，并用 `javac --release 8` 编译改名后的最小骨架。该测试不操作真实重命名对话框；安装后还需验证同名文件另存、非法输入提示、取消及原文件保留。

1.16.0 已移除 storage、SQLite/Flyway 与迁移资源，不增加转换或自动搬迁逻辑，不触碰历史数据库。运行时依赖检查包含数据库依赖，打包后还应确认 ZIP 不含数据库库文件、迁移资源、Notes/Submissions 实现。IDEA 自身包含 SQLite 类，不能以整个平台测试 classpath 上没有 SQLite 作为本插件无数据库依赖的判据。

## WebView 类型检查与运行时回归

WebView 保留 Vite/npm 构建链，共享运行时为 `webview/plugin/runtime.ts`；两页入口、宿主全局函数和资源注入契约集中维护在 [WebView 前端说明](../webview/README.md)。不要在构建插件中重新塞入大段运行时字符串。

Gradle `checkWebview` 执行 `npm run check`，依次运行 TypeScript 检查和 `runtime.test.mjs`。类型检查包含共享运行时的 DOM 空值与宿主接口；3 项运行时回归执行转译后的真实源码，只以替身提供 DOM、CSS 和 OverlayScrollbars，检查缩放限制／恢复、可选状态回调及容器缺失错误。Vite 打包由 `buildWebview` 执行，这些检查的职责不同。

产物检查应追踪两个页面入口到共享 chunk 的导入关系及 CSS／字体引用；`intellijStyle.css` 由 Kotlin 运行时提供，不应要求它作为静态文件存在。不要凭压缩后是否保留第三方函数原名判断模块丢失。真实 IDEA 仍需分别查看 Description／Solutions 的内容、代码高亮和公式表现，切换明暗主题，操作放大、缩小与原比例，并确认重新加载内容后缩放与宿主一致；自动检查不替代这部分验收。
