# 开发指南

## 环境与导入

使用 JDK 25 和 Node.js 24。Gradle 版本由 Wrapper 固定，npm 依赖由 `webview/package-lock.json` 固定。将 `JAVA_HOME` 指向 JDK 25，确保 `java`、`node` 和 `npm` 可用。

在 IDEA 中打开根目录并加载 Gradle 工程，设置 Gradle JVM 为 JDK 25。业务和 IDE 集成使用 Kotlin，Java 表单与 `.form` 继续保留，Gradle 处理联合依赖和表单插桩。Kotlin 运行库复用目标 IDE；开发和运行均不再要求 Scala 插件或 Scala 运行库。

`.editorconfig` 统一基础格式，不对历史 Flyway 迁移执行批量格式化。`.kotlin/` 会话目录与其他构建缓存一起忽略。

## 常用命令

从仓库根目录执行：

```bash
# 编译、执行离线测试并生成插件 ZIP
./gradlew check buildPlugin

# 启动独立沙箱 IDE 调试
./gradlew runIde

# 检查插件工程配置
./gradlew verifyPluginProjectConfiguration

# 检查平台 API 兼容性（需要下载验证器与目标 IDE）
./gradlew verifyPlugin

# 仅构建前端
./gradlew buildWebview

# 单独重新生成模板词法分析器
./gradlew generateLexer

# 检查运行时没有重新引入已移除的依赖栈
./gradlew verifyRuntimeLibraries
```

默认目标版本由 `gradle.properties` 的 `platformVersion` 决定，当前为 IDEA 2026.2.3；`platformSinceBuild` 限定最低平台构建号。修改后需要真实构建、API 兼容检查及客户端验收，不能仅改版本号宣布兼容。

需要复用本地 IDEA 以免重复下载时：

```bash
./gradlew check buildPlugin -PlocalPlatformPath="/path/to/IntelliJ IDEA.app"
```

本地平台路径只通过命令参数或个人 Gradle 配置提供，不写入仓库。切换目标版本时，确保该路径指向对应版本。

网络受限且构建依赖已缓存时，可以执行离线兼容性检查。Gradle 的 `--offline` 会同时传给 Plugin Verifier，使其仅解析本地已下载的插件依赖；未缓存的依赖仍会导致检查无法完成。

```bash
./gradlew verifyPlugin --offline -PlocalPlatformPath="/path/to/IntelliJ IDEA.app"
```


## 测试与验收

默认测试不调用真实力扣服务。已移除依赖个人 Cookie、固定本机代理和打印远端响应的手工 API 脚本。Kotlin JUnit 测试由 Gradle 的 `test` 执行；测试报告在 `build/reports/tests/test/`。

TLS 测试用 JDK 自带的 `keytool` 在临时目录生成证书，启动回环地址 HTTPS 服务，验证拒绝不可信证书，以及显式信任证书后仍检查主机名。私钥不检入仓库，测试结束后删除。协议测试使用本地响应替身。

回归覆盖旧 XML 和筛选条件、ID 与提交区域契约、V001 数据库升级、历史日期编码、事务回滚、跨题目关联校验、数据库切换、目录重命名、查询取消、虚拟文件路径以及 WebView 内容策略。插件描述符检查既验证类可加载，也验证自定义动作引用位于注册之后。这些检查不等于完整 IDEA 交互验收。

构建成功只证明代码与打包流程通过。安装后还需人工检查：两个站点的设置和题目入口、Login 对话框与浏览器页面、拉题、模板生成、测试、提交、提交记录及题解。使用测试账号和可丢弃的沙箱项目，真实提交由使用者自行执行。

客户端验收还应检查：设置修改后窗口立即更新；重启后语言、文件关联和筛选条件保留；快速切换筛选时旧响应不覆盖新结果；关闭视图或项目后请求停止；两个站点会话隔离；同站点在多个项目间登录/退出状态一致；旧提交详情、笔记和文件重命名仍可用。

CI 在推送和 Pull Request 时运行 `check buildPlugin verifyPluginProjectConfiguration`，上传 ZIP 及测试报告。手动运行 Build workflow 时还执行 `verifyPlugin` 并上传 `build/reports/pluginVerifier/`。修改目标平台或依赖后应执行这一检查；查看结论时同时关注兼容错误、待移除、废弃和实验性 API 报告。不自动发布到 JetBrains Marketplace。

## 网络与调试

HTTP 客户端使用正常的证书链和主机名校验，并读取 IDEA 的代理配置。使用组织代理或自签名证书时，将受信任的证书配置到运行 IDEA 的 JVM 信任库；不要用跳过校验的代码绕过错误。普通直连、代理和浏览器登录仍需在实际环境中验证。

`runIde` 首次启动可能需要下载 Gradle 插件的调试运行组件；离线运行前需先缓存相关依赖。开发时的运行组件不等于安装包中的运行库。

若 Gradle 报 JVM 版本错误，先核对启动 Gradle 的 `JAVA_HOME`，它与编译 toolchain 是不同的入口。若 Shell 中 `npm` 可用但已有 Gradle daemon 无法启动它，可用 `--no-daemon` 做一次验证，排除旧进程环境的影响，不把本机绝对路径写入构建脚本。

## 词法生成与数据库演进

维护源为 `src/main/grammar/ChallengeFileTemplateTextLexer.flex`。构建复用固定版本的 IntelliJ Platform Gradle Grammar-Kit 子插件，并固定 IntelliJ 版 JFlex 1.9.1；生成输出位于 `build/generated/sources/grammarkit-lexer/java/main/`。普通构建自动先生成再编译，无需手工复制 Java 文件，也不需要 Python。

修改词法规则后执行词法测试，核对嵌套引用、完整文本还原和 lexer reset。生成目录不纳入 Git，删除 `build/` 后应能完整重建。

数据库不再生成模型，也不维护平行设计 schema。结构调整新增 Flyway 迁移；同时更新 `storage/SqliteStore.kt` 的参数化 SQL、普通数据对象和数据库测试。旧迁移不能重写，UI 与执行流程不直接使用 JDBC。
