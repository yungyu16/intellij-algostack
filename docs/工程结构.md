# 工程结构

本项目是单模块 Gradle 工程，使用 Kotlin 实现业务与 IDEA 集成，保留 Java UI Designer 表单。仅支持 LeetCode 和 LeetCodeCN，通过稳定站点标识区分域名、会话和项目设置。

```text
build.gradle.kts               依赖、编译、WebView、词法生成和插件打包
settings.gradle.kts            Gradle 工程入口
gradle.properties             插件与目标平台版本
gradle/wrapper/               Gradle Wrapper
src/main/
  kotlin/                     业务、配置、存储与 IDEA 集成
  java/                       Java 表单类及对应 .form
  grammar/                    维护的 JFlex 词法规则
  resources/                  plugin.xml、消息、模板、图标和数据库迁移
src/test/
  kotlin/                     离线回归测试
  resources/                  脱敏的历史格式和模板样例
webview/                      题目描述、题解页面与 Vite 配置
docs/                         开发、结构和上游历史文档
build/generated/              构建时生成的词法分析器，不提交
build/distributions/          插件 ZIP，不提交
```

工程不再包含 Scala 源码、编译器或运行库，也不使用 jOOQ、HikariCP 或数据库代码生成。Scala 作为力扣支持的答题语言，其模板和图标仍保留。

## 职责与调用链

| 包 | 职责 |
|---|---|
| `domain` | 站点、语言、状态、分页和提交区域等规则；不依赖 IDEA UI 或数据库框架 |
| `leetcode/api` | OkHttp 协程客户端、GraphQL、协议模型及序列化 |
| `configuration` | IDEA 配置持久化、历史 XML 兼容、文件关联与配置事件 |
| `storage` | SQLite 连接、Flyway 迁移、SQL、事务、ID 序列和普通数据对象 |
| `runtime` | HTTP 客户端、Cookie、凭据、应用级登录态与项目任务 |
| `execution` | 手动打开与自动初始化共用模板和关联逻辑，另提供文件保护、测试和提交流程 |
| `automation` | 本机鉴权 HTTP 窄接口、实例发现和目标项目任务调度，不承载题解或平台提交 |
| `presentation` | 题目窗口、登录对话框、编辑器、侧栏、虚拟文件、WebView 与展示映射 |
| `settings`、`toolwindows/sidebar/notes` | Kotlin 设置控制器和笔记控制器；沿用 Java 表单绑定的包名 |
| `model/template`、`utils` | 模板词法、高亮和少量辅助组件 |

题目入口为 `plugin.xml → presentation.dojo.DojoWindowFactory → ChallengesView → LeetCodeClient`。打开题目进入 `execution.openChallenge`；编辑器动作进入 `ExecutionService`。侧栏统一通过 `SidebarContext` 跟随当前题目，通过 `ChallengeRepository` 读取本地数据，题解通过协程客户端读取。

展示名称、图标、颜色和 HTML 位于 `presentation/DomainPresentation.kt`。执行流程和界面使用存储层返回的普通 Kotlin 数据对象，不持有 JDBC Connection、ResultSet 或可自行写库的 ORM 记录对象。

## SQLite 与事务

SQLite JDBC 直接访问已有数据库，SQL 集中在 `storage/SqliteStore.kt`。不另维护设计 schema；数据库结构以 `src/main/resources/db/migration/` 为准。

`SqliteDatabase` 在项目内串行执行短数据库操作，每次操作打开并关闭连接。`ChallengeRepository.query` 和 `transaction` 在 IO 调度器执行；写操作必须处于事务中，异常时整体回滚。切换数据库目录后，后续操作解析新路径并执行对应迁移；关闭项目后不能重新打开连接。

界面菜单、筛选项和编辑器标题读取后台加载的快照。VFS 的文件恢复和保存接口是同步契约：恢复时允许读取记录；笔记保存必须在返回前持久化，不能改为无人等待的异步写入。切换数据库目录后，旧笔记虚拟文件拒绝继续写入，避免写错数据库。

保留旧日期的 Timestamp 文本写入格式，并兼容历史整数毫秒时间及高精度文本。提交取消或查询失败只将仍在处理中的记录标为未知，不覆盖已保存的最终结果。提交记录的语言与解法必须属于同一道题。

## 状态与资源生命周期

- HTTP 客户端、Cookie 和登录态属于应用；两个站点会话隔离，同站点在多个项目间共享登录状态。候选 Cookie 在隔离客户端中验证，成功后才替换现有会话。
- 数据库、配置、控制台和后台任务属于项目；界面自己的查询和订阅随视图关闭取消。
- 虚拟文件缓存属于项目，键包含完整项目路径标识；笔记和提交代码继续使用 `solution-remark`、`submission-code` 协议，路径解码兼容旧格式。
- WebView 本地资源服务器仅监听回环地址，只读取打包资源。页面 CSP 只许可构建模板中的脚本；远端 iframe 代理限制为 HTTPS 力扣站点。浏览器、请求任务和本地服务器随视图释放。

## 数据兼容与维护

保留插件 ID、动作 ID、配置组件名称、配置文件名、`leetcode` / `leetcodecn` 标识、数据库文件名和提交区域标记。历史筛选条件仍使用原保存键，即使键中包含已经删除的 Scala 类名，也不能随意改名。

已发布 Flyway 迁移的文件名和内容保持不变。历史迁移中的其他平台表与数据继续保留，但当前业务不访问或展示这些平台；数据库演进新增迁移，不重写旧迁移。

`CHANGELOG.md` 是当前版本更新说明的唯一来源。构建提取与 `pluginVersion` 对应的小节，生成插件描述符的 change-notes 和 `META-INF/release-notes.html`，IDE 通知读取后者。

词法分析器生成文件仅属于构建输出，不手工维护或提交；Java 表单类与 `.form` 按现有约定一起维护。`verifyRuntimeLibraries` 检查传递依赖，防止已经移除的 Scala、jOOQ 和连接池依赖再次进入运行时。上游归属和许可证保留在 README、LICENSE；上游历史不代表 fork 当前支持范围。
