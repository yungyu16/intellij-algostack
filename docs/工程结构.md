# 工程结构

本项目是单模块 Gradle 工程，业务、IDEA 集成与 Swing UI 均使用 Kotlin，不依赖 UI Designer 表单，仅支持 LeetCodeCN。1.16.0 起不使用本地数据库。

```text
build.gradle.kts               依赖、编译、WebView 和插件打包
gradle.properties             插件与目标平台版本
gradle/wrapper/               固定 Gradle 版本的 Wrapper
scripts/                      本机初始化 CLI 与 Node.js 测试
src/main/kotlin/               业务、配置与 IDEA 集成
src/main/resources/            plugin.xml、消息、模板和图标
src/test/                      离线回归测试
webview/                       题面和平台题解页面
docs/                          开发与维护文档
build/distributions/           插件 ZIP，不提交
```

## 职责与调用链

| 包 | 职责 |
|---|---|
| `domain` | 站点、语言/版本、内容身份识别、分页和提交区域规则 |
| `leetcode/api` | OkHttp 协程客户端、GraphQL、协议模型及序列化 |
| `configuration` | 应用级版本提示状态；不保存项目题目状态 |
| `runtime` | HTTP、Cookie、凭据、应用级登录态与项目任务 |
| `execution` | 模板渲染、文件保护、初始化、真实平台运行和提交 |
| `automation` | 本机鉴权 HTTP 窄接口与项目任务调度，不承载解法或提交 |
| `presentation` | 题库、编辑器工具栏、Console、题面、平台题解与 WebView |
| `utils` | 模板渲染辅助与通用组件 |

题库入口为 `plugin.xml → SidebarWindowFactory → ChallengesView → LeetCodeClient`。手动打开与自动初始化共用 `renderChallenge` 与 `ensureLanguageProject`，新文件用 `CREATE_NEW` 创建。所选 Java/Go 默认布局缺失工程时分别创建 Java 8 Maven `pom.xml` / 使用本机 Go 版本的 `go.mod`；已有描述文件原样保留，不提供自定义 source folder，不猜 module 根。已有匹配题目也检查工程，失败保留文件并返回 partial。编辑器动作进入 `ExecutionService`，运行和提交只调用真实平台 API，结果输出到 Console，并提供平台提交详情链接。不保存本地提交历史或笔记；Solutions 指平台题解文章，仍保留。

## 新题代码生成

`ChallengeConventions` 决定内置路径和模板，`renderChallenge` 组装平台数据、渲染文件名与代码，最后验证可信题目 URL 和唯一提交区域。手动打开与 Agent 初始化使用同一生成链路，已有源码不因模板升级而重写。

Java 的 `ChallengeTemplate.getCode()` 在提交区域包围之前调用 `JavaTemplateStub`：在 read action 中使用 IDEA 内置 Java PSI 解析临时文件，为没有语句的非构造方法补充 `UnsupportedOperationException("Not implemented")`，保留方法签名和注释。构造器、没有方法体的抽象方法及非空实现不处理；Go 不走这条转换，保留平台骨架。此处 Java PSI 依赖通过 `com.intellij.java` 声明，不新增外部解析器。题目身份识别仍沿用下文的轻量扫描，与生成时的 PSI 处理分开。

`JavaTemplateStubTest` 覆盖泛型、数组、void、throws、注释／字符串不误改、幂等、换行及最终 Java 8 编译；这些回归只证明对应骨架可生成，不表示解法已实现，也不保证所有平台题目在缺少题目专用类型时均可直接本地编译。

## UI 与状态边界

桌面 UI 由 Kotlin 直接构建 Swing 和 IntelliJ Platform 组件；题面、平台题解正文由 `webview/` 的前端页面展示。当前没有 `src/main/java/`、`.form` 或模板高亮词法规则目录，不需要 UI Designer 或 JFlex 生成代码。IntelliJ Platform Gradle Plugin 的标准字节码处理仍保留。

编辑器的文本组件与悬浮工具栏是兄弟组件，公共容器通过 `UiDataProvider` 提供 Project、VirtualFile、底层 Editor 和包装后的 FileEditor。选区动作读取这一组上下文，不能依赖工具栏从编辑器子树继承数据，或从全局焦点猜测目标编辑器；对应回归与边界见[开发指南](开发指南.md#编辑器工具栏上下文)。

编辑器工具栏和右键菜单不再提供自定义用例按钮；`TestCasesEditionAction`、`TestCasesDialog`、`TestCaseItemPanel` 已删除。测试时 `ExecutionService` 从当前平台响应的 `exampleTestcaseList` 构造输入，预期结果由平台执行响应提供，不缓存或保存用例。

项目级 `ChallengeSettings` 和路径关联的 VFS 监听已删除。打开题目、初始化、重命名和执行均不创建或更新 `challenge.xml`；旧文件保留在原处，但不读取、改写、迁移或删除。应用级版本提示状态和 PasswordSafe 凭据不属于项目题目状态，仍保留。自动检查与人工验收范围见[开发指南](开发指南.md#默认用例与无项目状态)。

### 查询结果发布与应用

查询结果沿 `submit → 后台执行 → StateFlow 发布 → EDT 应用` 流转，生产端和消费端分别保护：

- `LatestQuery` 在替换、取消或关闭请求时更新 generation；后台完成时核验请求代次和关闭状态，防止过期任务发布成功或失败结果。
- `ArticlesPanel` 的列表与正文消费者在进入 EDT 后、写入界面前调用 `isCurrent`。取消后台任务不能撤回已被消费者取出、正在等待 EDT 的结果，因此不能省略这次检查；请求替换／取消与 UI 应用在同一线程执行，检查和写入之间不挂起。
- 每次发布的 `Success`／`Failure` 实例兼作请求标识，按引用身份区分，不按业务内容去重。不能直接改回 data class：慢消费者可能错过中间的 Loading，导致旧实例被拒绝后，相同内容的新结果又被 StateFlow 合并而不再交付。

这里与 `SidebarContext` 的题目身份去重不同：相同题目身份不必重复触发加载，但新请求的相同结果仍需有机会应用。定向回归与人工验收见[开发指南](开发指南.md#查询结果与受理信息交付)。

## 题目身份与旧文件

核心身份为 `ChallengeIdentity(站点, slug, 语言, 语言版本)`，不再生成数据库本地 ID，也不以哈希伪造 ID。普通编辑器打开只读取本地内容，不联网。

`ChallengeRecognition` 对 Java/Go 全文件扫描真实行注释和块注释，再提取 HTTPS 力扣题目 URL；没有头部位置要求，允许 package/import 后、类或方法内、代码同行尾部的注释。字符串、字符、转义、Java 文本块和 Go raw string 中的 URL 不采信。BOM、LF、CRLF 和 CR 均兼容。不检查 package 声明是否合法或代码是否可编译，也不展开 Java Unicode 转义，不引入完整 Java/Go Parser。

多个不同题目 URL、缺少唯一提交区域或普通文件不作为题目；同题重复 URL 可以共存。生成器只渲染内置模板并验证题目 URL 和唯一提交区域，不再强制附加重复 URL 或 `leetcode-editor:` 头。Java／Go 默认模板自身包含题目 URL；不改写用户已有文件或旧模板设置。

1.17.0 移除外部身份兜底：`recognize(text, extension)` 不接收 XML 身份。站点和 slug 必须来自上述可信 URL；语言由扩展名唯一确定，版本固定为 AnyVersion，不生成或解析 language/version metadata。没有 URL 的文件即使存在带 slug、语言/版本的 XML 关联，或只有提交区域，也不能识别。XML 不得补全站点、slug、语言或版本，共用扩展名的其他语言因无法唯一确定语言而拒绝识别，不增加兼容兜底。

`utils/ChallengeFiles.resolve` 是无状态识别入口：优先读取 cached Document（包含未保存修改），无缓存时回退 VFS，再调用 `ChallengeRecognition`，只返回 `ChallengeIdentity`。没有项目服务、路径映射或本地标题／用例快照；删除、移动或重命名文件不需要更新关联。源码需要真实注释中的 URL 与唯一提交区域，不需要版本注释或数据库转换。新题与实际执行沿用固定 Java／Go AnyVersion，平台语言 slug 分别为 `java`／`golang`；Java 工程的 Maven source/target 8 是本地编译约定，不是平台执行版本。

### URL 与提交区域的兼容边界

- URL 从注释文本正则提取后交给 `URI` 校验，只接受小写 `https://` 和精确主机 `leetcode.cn` / `www.leetcode.cn`，不接受 userinfo、任何显式端口（包括 443）、HTTP、伪装主机或非题目路径。不能从恶意主机/路径或单词内截取 CN 子串充当可信链接。其他不可信链接忽略，不贡献候选。
- 显式 HTTPS 国际站主机 `leetcode.com` / `www.leetcode.com` 出现在真实注释中时拒绝整份身份，即使同时存在可信中国站 URL；这是保留的防止跨站误关联策略，不自动转换站点，也不从 XML 回退。
- 路径接受 `/problems/<slug>` 及其任意子路径（如 description、solutions、submissions），不验证子页存在；query/fragment 不参与 slug 判断。同题不同子页可共存，不同 slug 拒绝。
- 提取排除空白、`< > " ' ( ) [ ]`，剥去末尾 ASCII `. , ; * !` 和常见中文 `，。；！）`，兼容常见 Markdown 链接、括号及注释边界；不是通用 Markdown/HTML 解析器。
- `SourceRegions` 为 Java/Go 共享注释扫描器及所有语言的唯一提交区域定位器。Java/Go 标准 Begin/End 必须各有且仅有一条独占行真实 `//` 注释，Begin 在 End 前；块注释中的区域示例不算边界。缺失、倒序、多段、额外 Begin/End 或嵌套歧义均拒绝。
- `Language.extractCodeFromRegion` 使用同一定位器截取原文偏移，不再按原始行另行挑选或拼接区域；识别所确认的边界与运行/提交提取一致，保留区域内换行及所有原始代码（包括代码中的伪标记字符串）。无有效边界时返回空串，执行入口拒绝空提交。
- 其他现有语言保留头部注释身份扫描与各自整行模板标记语法（如 Python `#`、SQL `--`、OCaml `(*...*)`），未宣称支持其全文件词法语义；识别和提取同样共用唯一定位规则，不再允许多区域拼接。枚举回归验证所有语言的区域提取，以及扩展名唯一时的识别、扩展名歧义时的拒绝。本次全文件真实注释/字面量处理的保证范围为 Java/Go。

文件名中的题号只作展示辅助，不用于猜测提交身份，也不新增题号 fallback；可信 URL slug 优先，frontend 题号不能替代后台 questionId。

题面在 Description 中实时请求 `getQuestionData(slug)`。运行、提交及旧题默认用例按需异步请求平台数据；提交使用后台 `questionId`，绝不使用展示用 `frontendQuestionId`。平台失败显示错误，不伪装成空题面成功，也不自动重试不确定的提交写入。

## 配置与窗口策略

- root 的 `.leetcode` 仅是启用标记，兼容文件和目录。无标记时启动活动直接退出，整个工具窗口不注册，不启动登录恢复/本机桥接；编辑器 provider、图标/动作也跳过业务服务。不会创建、更改或搬迁标记内容。标记变更后重新打开项目以重新判定工具窗口适用性。
- 新题按 `ChallengeConventions` 固定提供 Java／Go AnyVersion 的目录和内置模板，不提供 Settings 页面。旧 `.idea/CodeEpiphany/leetcodecn.xml` 中的语言、路径、模板、CSS 不再读取；不删除、改写或迁移旧配置。题面样式跟随 IDE 主题。
- `queryCriteria`、筛选、关键词、排序、分页和查询模式只在视图内存中存在，不读取或写回偏好 XML。账号凭据仍不属于可共享的项目配置。
- 题库固定为 `Problems`，和 `Console` 构成默认两页，不依赖语言配置。`ProblemQueryState` 管理已提交条件与分页，`ProblemSearchBar` 只持有各范围输入草稿；Enter/按钮显式提交。筛选/排序/翻页不读取草稿；范围切换保留筛选、关键词和草稿，重置目标范围排序并回首页。首行原生 JComboBox / JTextField / JButton，筛选工具栏另行、无筛选标签时隐藏标签行。
- `SidebarContext` 以当前编辑器内容身份驱动 Description/Solutions。在 EDT 读取编辑器选择，后台 read action 内优先读取 cached Document（含未保存修改），无缓存时只读 VFS，取消检查后在 EDT 发布身份。非题目编辑器隐藏这两页，但保留题库与 Console；焦点进入或切换工具窗口 tab 不清除所选题目，也不主动打开/切换编辑器。内容变化会重新识别；相同身份由 StateFlow 去重，不重复触发题面加载。此调用链核对不代替真实 IDEA 交互验收。

## 资源生命周期与数据边界

HTTP 客户端、Cookie、CredentialsStore 和 AuthService 登录态属于应用；中国站跨项目共享；国际站不再枚举、恢复或读取凭据。标记项目启动活动不依赖视图，通过既有 ensureAuthenticated 静默校验保存会话；entry Mutex 串行化，应用内每站点完成一次自动恢复尝试（包括无凭据/失败），取消不缓存。手动 Login 可重试并走原交互回退，不自动打开浏览器。控制台、配置与后台任务属于项目；面板查询随视图关闭取消。取消提交跟踪不会撤销平台已经受理的提交。Accepted 事件交付到执行层后，Console 对提交 ID 与平台链接的本地输出提供短暂取消保护，保护包括等待 EDT；输出前在 EDT 检查项目和 Console 是否已释放，完成后恢复取消检查，不保护后续网络轮询。服务端已受理但响应或 Accepted 尚未交付时，客户端仍可能没有准确 ID，此时只提示到平台核对，不承诺能恢复该链接。

WebView 本地服务器仅监听回环地址，只读取打包资源；远端 iframe 代理限制为 HTTPS 力扣站点。浏览器、请求任务和服务器随视图释放。两页通过显式导入共用 `webview/plugin/runtime.ts` 的滚动条与缩放逻辑，Vite 插件仅注入动态主题样式入口和回调；Kotlin 保有缩放状态并提供 `intellijStyle.css`。跨语言接口与构建产物约定见 [WebView 前端说明](../webview/README.md)。

本版本删除 `storage`、SQLite/Flyway 依赖与迁移资源，以及本地 Notes/Submissions 和相关虚拟文件协议。**不会打开、迁移、删除或改写用户已有数据库**；旧库中的历史提交和笔记不再由新版本展示，文件由用户自行保留。项目中没有新旧数据库转换流程。

保留插件 ID、内置模板路径与提交区域契约；不读取项目 XML 或访问旧库。`CHANGELOG.md` 旧版本条目是历史记录，不代表当前行为。构建从当前版本条目生成插件更新说明。`verifyRuntimeLibraries` 禁止 SQLite/Flyway、Scala、jOOQ 和连接池重新进入插件依赖；IDEA 自身携带的数据库组件不属于本插件运行库。
