# 工程结构

本项目是单模块 Gradle 工程，业务与 IDEA 集成使用 Kotlin，保留 Java UI Designer 表单，仅支持 LeetCode 和 LeetCodeCN。1.16.0 起不使用本地数据库。

```text
build.gradle.kts               依赖、编译、WebView、词法生成和插件打包
gradle.properties             插件与目标平台版本
src/main/kotlin/               业务、配置与 IDEA 集成
src/main/java/                 Java 表单及 .form
src/main/grammar/              JFlex 词法规则
src/main/resources/            plugin.xml、消息、模板和图标
src/test/                      离线回归测试与脱敏历史 XML 样例
webview/                       题面和平台题解页面
docs/                          开发与维护文档
build/generated/               构建生成的词法分析器，不提交
build/distributions/           插件 ZIP，不提交
```

## 职责与调用链

| 包 | 职责 |
|---|---|
| `domain` | 站点、语言/版本、内容身份识别、分页和提交区域规则 |
| `leetcode/api` | OkHttp 协程客户端、GraphQL、协议模型及序列化 |
| `configuration` | 稳定模板配置、文件用例关联与旧 XML 读取 |
| `runtime` | HTTP、Cookie、凭据、应用级登录态与项目任务 |
| `execution` | 模板渲染、文件保护、初始化、真实平台运行和提交 |
| `automation` | 本机鉴权 HTTP 窄接口与项目任务调度，不承载解法或提交 |
| `presentation` | 题库、编辑器、Console、题面、平台题解与 WebView |
| `settings` | Kotlin 设置控制器，复用 Java 表单 |
| `model/template`、`utils` | 模板词法、高亮和辅助组件 |

题库入口为 `plugin.xml → SidebarWindowFactory → ChallengesView → LeetCodeClient`。手动打开与自动初始化共用 `renderChallenge` 与 `ensureLanguageProject`，新文件用 `CREATE_NEW` 创建。所选 Java/Go 默认布局缺失工程时分别创建 Java 8 Maven `pom.xml` / 使用本机 Go 版本的 `go.mod`；已有描述文件原样保留，自定义 source folder 必须已有明确工程，不猜 module 根。已有匹配题目也检查工程，失败保留文件并返回 partial。编辑器动作进入 `ExecutionService`，运行和提交只调用真实平台 API，结果输出到 Console，并提供平台提交详情链接。不保存本地提交历史或笔记；Solutions 指平台题解文章，仍保留。

## 题目身份与旧文件

核心身份为 `ChallengeIdentity(站点, slug, 语言, 语言版本)`，不再生成数据库本地 ID，也不以哈希伪造 ID。普通编辑器打开只读取本地内容，不联网。

`ChallengeRecognition` 从源文件头部注释中读取 HTTPS 力扣题目 URL，并要求有效的提交区域。支持 `leetcode.com`、`leetcode.cn` 及其 `www` 域名；Java/Go 旧题不需要先有带 slug 的 XML。1.16.1 起允许题面注释和生成的 URL / language-version metadata 位于一个合法 Java/Go `package` 声明之前或之后，兼容文件起始 BOM、空白、Java 多段包名及 Go `package main`；Java 声明须以分号结束，Go 须有换行、显式分号或行末注释边界。

扫描在 `import` 或其他代码处停止：URL 在 import 前的头部注释中可识别，只有 import 后或实现体中的 URL 不可识别。不会跳过任意以 `package` 开头的代码；不实现完整语言解析（如 Java package 注解、包名内夹注释、Unicode 转义及 Go 包名后同一行的块注释）。其他语言不增加 package 特例。多个不同题目 URL、冲突 metadata、非可信主机、代码字符串中的 URL、缺少提交区域或普通文件不作为题目。生成文件增加 URL 和语言/版本注释，不改写用户已有文件或模板设置。

新关联可保存 slug、语言/版本、标题和用例；旧 XML 没有 slug 时仅在内容识别成功且站点、语言匹配时读取用例，不把旧数据库 ID 当作身份。没有可信 URL、也没有有效新关联的旧文件不能自动识别：用户可自行补充头部题目 URL 与提交区域，不需要数据库转换。未知的旧语言版本不能从本地 ID 推断；新生成文件明确记录版本。

题面在 Description 中实时请求 `getQuestionData(slug)`。运行、提交及旧题默认用例按需异步请求平台数据；提交使用后台 `questionId`，绝不使用展示用 `frontendQuestionId`。平台失败显示错误，不伪装成空题面成功，也不自动重试不确定的提交写入。

## 配置与窗口策略

- root 的 `.leetcode` 仅是启用标记，兼容文件和目录。无标记时启动活动直接退出，整个工具窗口不注册，不启动登录恢复/本机桥接；编辑器 provider、图标/动作及关联变更监听也跳过业务服务。不会创建、更改或搬迁标记内容。标记变更后重新打开项目以重新判定工具窗口适用性。
- 稳定语言、模板与 CSS 保留 IDEA 项目 Storage：`.idea/CodeEpiphany/leetcode.xml` 和 `leetcodecn.xml`，可由使用者按明确路径加入 Git。插件不会自动把配置从 `.idea` 搬到 `.leetcode`，也不反向搬迁历史副本。
- `queryCriteria`、筛选、关键词、排序、分页和查询模式只在视图内存中存在，不读取或写回偏好 XML。账号凭据仍不属于可共享的项目配置。
- `SidebarContext` 以当前编辑器内容身份驱动 Description/Solutions。在 EDT 读取编辑器选择，后台 read action 内优先读取 cached Document（含未保存修改），无缓存时只读 VFS，取消检查后在 EDT 发布身份。非题目编辑器隐藏这两页，但保留题库与 Console；焦点进入或切换工具窗口 tab 不清除所选题目，也不主动打开/切换编辑器。内容变化会重新识别；相同身份由 StateFlow 去重，不重复触发题面加载。此调用链核对不代替真实 IDEA 交互验收。

## 资源生命周期与数据边界

HTTP 客户端、Cookie、CredentialsStore 和 AuthService 登录态属于应用；同站点跨项目共享，两站隔离。标记项目启动活动不依赖视图，通过既有 ensureAuthenticated 静默校验保存会话；entry Mutex 串行化，应用内每站点完成一次自动恢复尝试（包括无凭据/失败），取消不缓存。手动 Login 可重试并走原交互回退，不自动打开浏览器。控制台、配置与后台任务属于项目；面板查询随视图关闭取消。取消提交跟踪不会撤销平台已经受理的提交，Console 保留已获得的平台链接。

WebView 本地服务器仅监听回环地址，只读取打包资源；远端 iframe 代理限制为 HTTPS 力扣站点。浏览器、请求任务和服务器随视图释放。

本版本删除 `storage`、SQLite/Flyway 依赖与迁移资源，以及本地 Notes/Submissions 和相关虚拟文件协议。**不会打开、迁移、删除或改写用户已有数据库**；旧库中的历史提交和笔记不再由新版本展示，文件由用户自行保留。项目中没有新旧数据库转换流程。

保留插件 ID、两站配置组件名称、稳定模板路径与提交区域契约。`CHANGELOG.md` 旧版本条目是历史记录，不代表当前行为。构建从当前版本条目生成插件更新说明。`verifyRuntimeLibraries` 禁止 SQLite/Flyway、Scala、jOOQ 和连接池重新进入插件依赖；IDEA 自身携带的数据库组件不属于本插件运行库。
