# 工程结构

本项目是单模块 Gradle 工程：业务、IDEA 集成与 Swing UI 使用 Kotlin，题面和题解正文使用 TypeScript/JCEF，仅支持 LeetCodeCN。构建、测试和安装见[开发指南](开发指南.md)，外部调用协议见[挑战初始化桥接接口](挑战初始化桥接接口.md)。

## 目录与职责

| 位置 | 职责 |
|---|---|
| `build.gradle.kts`、`gradle.properties`、`gradle/wrapper/` | 依赖、版本、WebView 构建与插件打包 |
| `src/main/kotlin/io/github/yungyu16/algostack/domain/` | 题目身份、语言、分页和提交区域规则 |
| 同包下 `leetcode/`、`leetcode/model/` | 力扣客户端、JSON 编解码与站点协议模型 |
| `src/main/resources/graphql/` | 当前中国站使用的 GraphQL 请求，保留 `_cn` 优先及无后缀回退 |
| `runtime/`、`configuration/` | HTTP、凭据、登录态、项目任务与应用级版本提示状态 |
| `execution/` | 模板、文件保护、语言工程初始化、平台测试和提交 |
| `automation/` | 本机鉴权桥接与目标项目任务调度 |
| `presentation/problems/` | 题库视图、筛选、搜索、查询条件与请求快照 |
| `presentation/editor/` | 文本编辑器包装、动作、标题及提交区域折叠 |
| `presentation/sidebar/`、`presentation/browser/` | 侧边栏上下文、题面／题解面板和 JCEF 渲染 |
| `presentation/`、`utils/` | 跨视图动作上下文、查询发布、Console、展示转换与通用辅助逻辑 |
| `src/main/resources/` | 插件描述符、消息、图标、GraphQL 和内置模板 |
| `src/test/`、`scripts/` | 离线回归与 Node 初始化客户端 |
| `webview/` | 两个 JCEF 页面及共享运行时 |
| `build/distributions/` | 生成的插件 ZIP，不提交 |

目录按实际职责归组：题库实现集中在 `presentation/problems`，共享查询协调仍在 `presentation/LatestQuery`；模板专用 `VelocityTool` 与生成逻辑一起放在 `execution`，不作为通用工具暴露。客户端不再叠加单一 `api` 中间层。测试沿对应生产包组织；基础包、插件 ID、配置和凭据标识不随目录调整改变。

主要调用链：

- 题库：`plugin.xml → SidebarWindowFactory → ChallengesView → LeetCodeClient`。
- 手动新题：`OpenChallenge → renderChallenge → ensureLanguageProject → saveNewFile → 打开编辑器`。
- 自动初始化：`ChallengeBridgeServer → ChallengeAutomation → initializeChallenge → 新建／核验题目 → 检查语言工程 → 打开编辑器`。
- 测试／提交：`编辑器动作 → ExecutionService → 当前内容识别与保存后复核 → 平台题目数据 → 测试／提交 → Console`。

## 新题代码生成

`ChallengeConventions` 唯一定义 Java／Go AnyVersion 的模块根、源码目录、命名和模板，不读取旧语言、路径、模板或 CSS 设置。数字题号至少补齐四位，非数字题号沿用 slug 驼峰名称；已有文件不因模板升级而重写。

`renderChallenge` 使用真实 Velocity 模板渲染，再验证可信题目 URL 和唯一提交区域。模板统一提供展示题号、标题（优先中文、缺省英文）、URL，并以空行分隔题面；不附加重复头部或 language/version metadata。标题中的换行转为空格、`*/` 转为 `* /`，避免破坏块注释。`${challenge.descriptionText}` 对 HTML 做有限纯文本转换，保留比较符、泛型文本、换行和未知标签，`sup/sub` 转为 `^/_`，图片保留地址，注释终止符 `*/` 转为 `* /`；它不是通用排版器或安全过滤器。`${challenge.description}` 仍提供 HTML。

Java 的 `ChallengeTemplate.getCode()` 使用 `JavaTemplateStub` 在 read action 中解析临时 Java PSI，给无语句的非构造方法加入 `throw new UnsupportedOperationException("Not implemented");`。方法签名、注释、构造器、抽象方法和非空实现不变；Go 使用 `GoTemplateStub` 对平台骨架做轻量词法扫描，忽略注释和字符串内的结构符号，只为以 `func` 起行的顶层空函数／方法填入 `panic("Not implemented")`，保留非空实现、类型和函数字面量；不依赖 Go 插件，也不是通用 Go 重写器。Java PSI 依赖由 `com.intellij.java` 声明，生成时解析与身份识别的轻量扫描职责不同。`PreparedChallenge` 仅携带最终文件、代码与身份，模板输入只在渲染阶段存活。骨架可编译不代表解法完成，缺少题目专用类型时仍可能无法直接本地编译。

手动同名另存由 `saveNewFile` 确定最终路径，再调用 `PreparedChallenge.codeForFile`。`GeneratedChallengeFile` 只替换新骨架中原文件名对应的顶层 `public` 类声明，拒绝非法类名，并检查提交区域原文不变；不做全局替换，不修改已有文件，也不是通用重命名重构。Agent 入口不弹重命名对话框，按固定路径返回结果。

### 语言工程初始化

- 仅创建所选语言的工程：Java 默认在 `code/java` 生成 Java 8 Maven 最小 `pom.xml`，源码位于 `src/main/java/leetcodecn`；Go 默认在 `code/go` 生成 `module leetcode-practice`，每题位于 `leetcodecn/<题目名>/main.go` 的独立目录，题目名采用小写下划线（如 `p0001_two_sum`），与 Java 类名风格区分。
- Go directive 取本机 `go version` 的 major.minor。查询设置 `GOTOOLCHAIN=local`、`GOWORK=off`，有超时，不下载工具链；没有 Go 时需安装或自行准备 `go.mod`。已有描述文件不要求查询 Go，也不执行 Maven 或依赖下载。
- 从固定源码目录向上查找至项目根，遇到已有同语言 `pom.xml`／`go.mod` 就复用，不解析或改写。若先遇到 Java 的 Gradle 配置或 Go 的 `go.work`，要求用户明确建立目标工程，不猜多模块归属。没有描述文件时只允许按默认布局创建，不提供自定义 source folder。
- 路径须在项目内且父目录无软链接；描述文件须为普通文件。工程检查进程内串行，所有新文件使用 `CREATE_NEW`。并发已创建的普通描述文件只复用，不截断；不防御同用户恶意换目录，不修复其他进程留下的不完整文件。
- 手动入口先检查工程再保存题目；Agent 先创建／核验骨架再检查工程，已有匹配题目也执行工程检查。失败时保留已有成果并返回 `partial`。文件、工程和编辑器不构成跨资源事务，取消、崩溃或 I/O 故障可能留下部分结果，不自动回滚用户数据。

## 题目身份与旧文件

核心身份为 `ChallengeIdentity(站点, slug, 语言, 语言版本)`，不使用数据库 ID、哈希 ID 或文件名中的题号猜测身份。新题和实际执行固定使用 AnyVersion，平台语言 slug 为 `java`／`golang`；本地 Maven Java 8 约定不是平台执行版本。

`ChallengeRecognition` 从 Java/Go 全文件的真实行注释和块注释提取题目 URL，允许 package/import 后、类或方法内及行尾注释。字符串、字符、转义、Java 文本块和 Go raw string 中的 URL 不采信；支持 BOM、LF、CRLF 和 CR。不检查代码是否可编译，不展开 Java Unicode 转义，不引入完整 Java/Go Parser。

`ChallengeFiles.resolve` 优先读取 cached Document（含未保存修改），否则读取 VFS，调用方负责 read action。身份识别本身不联网；打开已启用项目的题目文件时，中文 tab 标题会后台请求平台。执行保存后按文本再次复核身份。题面、默认用例和后台 questionId 按需请求平台，展示题号不能替代后台 questionId。平台失败显示错误，不伪装成空结果，不自动重试不确定的提交写入。

### URL 与提交区域的兼容边界

- URL 由注释正则提取后交给 `URI` 校验，只接受小写 `https://` 和精确主机 `leetcode.cn`／`www.leetcode.cn`；拒绝 userinfo、任何显式端口（包括 443）、HTTP、伪装主机或非题目路径，不能从恶意链接内部截取可信子串。
- 真实注释中的显式 HTTPS 国际站 `leetcode.com`／`www.leetcode.com` 会使整份身份被拒绝，即使同时有中国站 URL；其他不可信链接不贡献候选，不自动转站。
- 接受 `/problems/<slug>` 及任意子路径，不验证子页存在；query/fragment 不影响 slug。同题重复 URL 可共存，不同 slug 拒绝。
- 提取排除空白、`< > " ' ( ) [ ]`，剥去末尾 ASCII `. , ; * !` 和常见中文 `，。；！）`，兼容常见 Markdown 和注释边界，不是通用 Markdown/HTML 解析器。
- Java/Go 的 Begin/End 必须各为一条独占行真实 `//` 注释，且 Begin 在 End 前；块注释示例、字符串伪标记不算边界。缺失、倒序、多段、额外标记或嵌套歧义均拒绝。
- `SourceRegions` 同时服务识别与提取。`Language.extractCodeFromRegion` 按同一边界截取原文偏移，保留区域内全部代码和换行；没有唯一边界返回空串，执行入口拒绝空提交。
- 其他既有语言保留头部注释扫描和各自整行标记，不宣称具备 Java/Go 的全文件词法保证，也不开放新题生成。扩展名无法唯一确定语言时拒绝识别。

没有 URL 的旧文件即使有关联 XML 或提交标记也不能识别；不从 XML 补充站点、slug、语言或版本，不解析 language/version metadata。重命名或移动文件无需更新任何关联。

## UI 与状态边界

Swing 组件由 Kotlin 构建，不维护 `.form`、UI Designer 或模板高亮词法生成；平台标准字节码处理仍保留。

- root `.leetcode` 文件或目录仅作启用标记，不改写内容。无标记不注册工具窗口、不恢复登录或启动桥接，编辑器增强也跳过业务服务；标记变更后重新打开项目。
- 默认 `Console`／`Problems`。`SidebarContext` 在 EDT 读取选中文件、后台 read action 读取身份，再经取消检查回到 EDT 发布。非题目隐藏 Description/Solutions；切换工具窗口 tab 不清题目、不强制切换编辑器。相同题目身份由 StateFlow 去重，避免重复加载题面。
- `ProblemQueryState` 保存内存中的已提交条件，`ProblemSearchBar` 保存输入草稿。Enter／按钮提交搜索；筛选、排序、翻页使用已提交关键词。切换范围保留各自条件和草稿、回首页并重置排序。不持久化 queryCriteria，也不保留旧查询保存格式的 serializer；通过显式 `.api()` 映射请求参数。
- `ProblemFilters` 负责选项与切换，`ProblemPageRequest` 固定请求快照；普通查询使用 categorySlug／listId／difficulty／status／tags，公司查询使用 favoriteSlug 和 filtersV2，未选公司不发查询。不把本地 mock 结果当作远端筛选语义的证明。

### 编辑器集成

文本组件和悬浮工具栏是兄弟组件，公共 `UiDataProvider` 显式提供 Project、VirtualFile、底层 Editor 和包装后的 FileEditor；不能依赖全局焦点猜测选区所属编辑器。

返回 `HIDE_DEFAULT_EDITOR` 的 Provider 须实现 `DumbAware`，且创建链路不能依赖索引。Kotlin 的 `by` 不转发 Java 接口默认方法，`DelegatingTextEditor` 因而显式转发文件、状态、加载就绪、通知及相关能力。属性事件通过桥接将 source 改为平台登记的包装器，保留属性名、旧／新值和 propagationId，不修改原事件；监听器按对象身份管理，重复注册逐次移除。

### 查询结果发布与应用

查询沿 `submit → 后台执行 → StateFlow 发布 → EDT 应用` 流转：`LatestQuery` 用 generation 和关闭状态拒绝过期发布；`ArticlesPanel` 进入 EDT 后以 `isCurrent` 拒绝已取出但失效的结果，请求替换／取消与 UI 应用在同一线程，检查和写入之间不挂起。

成功／失败终态实例兼作请求标识，不能直接改为按业务内容判等的 data class。慢消费者可能错过 Loading；若新旧结果被 StateFlow 合并，旧实例被拒绝后，新结果也不会交付。这与题目身份去重不同：同一身份无需重复触发加载，但新请求的同内容结果仍需有机会应用。

Solutions 的预览从属于当前选择：列表刷新、替换及选择调整／清空都会取消旧详情并清空正文，稳定选择后才加载新详情；已排队的旧结果仍须通过 `isCurrent`。题解详情查询只消费正文，列表作者、摘要、会员和点赞信息由列表 DTO 提供。

## 资源生命周期与数据边界

HTTP、Cookie、CredentialsStore 和 AuthService 为应用级，中国站跨项目共享。标记项目启动时静默调用 `ensureAuthenticated`，不依赖视图；每站点在应用生命周期内最多完成一次自动恢复尝试，包括无凭据或失败，取消不计为完成。手动 Login 可重试并回退到 Cookie／浏览器交互；不读取或删除国际站凭据，不在后台循环重试。

认证恢复、验证与退出由 `AuthenticationSession` 的 Mutex、generation/revision 和取消保护协调；普通业务响应更新 Cookie 的完整跨请求隔离，以及 PasswordSafe 已写入后再抛异常的情况，不具备跨组件事务保证。实际代理、PasswordSafe、浏览器和多项目行为仍需客户端验证。

控制台和后台任务属于项目，查询随视图关闭取消。测试输入只取本次平台返回的 `exampleTestcaseList`，结果进入 Console；没有自定义用例或本地提交历史。取消提交不撤回远端操作：Accepted 交付到执行层后，短暂取消保护覆盖 ID／链接的 EDT 排队与输出，输出前检查项目和 Console 是否释放，完成后恢复取消检查，不保护网络轮询。响应或 Accepted 尚未交付时可能没有准确 ID，只能提示到平台核对。

桥接 HTTP 服务属于应用，初始化属于目标项目；取消后等待项目任务结束再释放串行锁，阻塞文件 I/O 不保证立即中断。协议、安全和调用方处理统一见[桥接接口](挑战初始化桥接接口.md)，不在这里维护第二份错误码表。

题目 tab 标题由项目级 `ChallengeEditorTitles` 按源码身份后台加载，优先中文题名、缺省英文；加载中、失败或无标题时保留文件名。只保留打开文件的内存状态，不依赖 `ChallengeEditor` 已创建，不写数据库或 XML。身份变化及文件关闭取消旧请求，发布前复核身份与请求实例；失败结果不随 presentation 回调反复重试，关闭重开可重新加载。标题 Provider 在获取服务前检查启用标记；文档监听忽略非本项目打开文件，只在身份或标题变化时刷新展示。

WebView 服务器仅监听回环地址、只读取打包资源，远端 iframe 代理限 HTTPS 力扣站点；浏览器、请求任务和服务器随视图释放。两页显式导入 `webview/plugin/runtime.ts`；Kotlin 持有缩放状态、提供动态 `intellijStyle.css`。双侧契约集中在 [WebView 前端说明](../webview/README.md)。Solutions 只在面板内阅读：作者名／头像仅展示，列表选中后加载右侧正文，不再双击打开作者主页。题解模式仅允许宿主当前页面和片内锚点，拦截其他主页面导航、新标签页及弹窗；内嵌 frame 可自动加载，但不接受用户点击导航。Description 的链接行为及全局提交详情、账号入口不受此限制。

**旧数据库和项目 XML 均不读取、改写、迁移或删除。** 不再展示旧笔记、提交历史或自定义用例，不读取旧模板、路径、CSS 和查询设置；保留插件 ID、站点标识、配置与凭据锚点。应用级版本提示及 PasswordSafe 凭据仍保留。`verifyRuntimeLibraries` 防止 SQLite/Flyway、Scala、jOOQ 和连接池重新进入插件运行库；IDEA 自带的数据库组件不属于本插件依赖。
