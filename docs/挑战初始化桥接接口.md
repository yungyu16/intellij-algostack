# 挑战初始化桥接接口（Challenge Bridge）

题栈在本机 `127.0.0.1` 随机端口上提供两个 HTTP 接口，供本机 Agent 或脚本自动化创建新题目骨架（Java／Go）。这是唯一开放给 IDEA 之外的入口：没有任意文件写入、代码执行或平台测试/提交能力。

- 提供方：插件 `AlgoStackStartupActivity` 在**标记项目**（root 含 `.leetcode` 文件或目录）打开时启动，一个 IDE 实例一个端口。
- 实现位置：`src/main/kotlin/com/wenjunhuang/algostack/automation/`（`ChallengeAutomation.kt` 服务端生命周期，`ChallengeBridgeServer.kt` HTTP 层）。
- 配套 Node 客户端：`scripts/initialize_challenge.mjs`，可直接 CLI 使用或作为库引用。

## 发现入口（描述文件）

端口与鉴权 token 通过描述文件发布：

- 目录：`~/.local/state/algostack/bridge/`
- 文件名：`<IDEA进程号>.json`，内容为 UTF-8 JSON：

```json
{
  "version": 1,
  "pid": 12345,
  "port": 54321,
  "token": "64 位十六进制随机字符串"
}
```

- 目录权限 `0700`、文件权限 `0600`；客户端应校验文件所有者为当前用户且无组/其他权限，不校验则视为不可信。IDEA 正常退出时删除自己的描述文件；崩溃后的过期文件保留，由 `/status` 探测淘汰，不自动删除。
- 历史版本使用 `~/.local/state/yy-leetcode/bridge/`，升级后旧目录不再写入，也不删除。

## 通用请求约定

所有请求必须满足，否则返回 `403 {"error":"forbidden"}`：

1. 只接受来自 `127.0.0.1` 的连接；
2. `Host` 头必须是 `127.0.0.1:<端口>`（防 DNS 重绑定）；
3. 不能携带 `Origin` 头（防浏览器页面发起）；
4. `Authorization: Bearer <token>`（token 来自描述文件）。

响应统一为 JSON，`Content-Type: application/json; charset=utf-8`，带 `Cache-Control: no-store`。

## 接口

### GET /status

返回当前实例可见的标记项目列表（真实路径）：

```json
{
  "version": 1,
  "projects": ["/Users/me/code/oh-my-algo"]
}
```

用途：探测描述文件是否活着、确认目标项目已在该 IDE 实例中打开。超时建议 2 秒。

### POST /initialize-challenge

请求头 `Content-Type: application/json`，请求体（上限 4096 字节）：

```json
{
  "project": "/Users/me/code/oh-my-algo",
  "slug": "two-sum",
  "language": "java",
  "dojo": "leetcodecn"
}
```

| 字段 | 约束 |
|---|---|
| `project` | 必须与 `/status` 返回的某个真实路径完全一致 |
| `slug` | 小写字母/数字连字符，≤160 字符，如 `two-sum` |
| `language` | 只接受 `java` 或 `go` |
| `dojo` | 只接受 `leetcodecn`（可省略，默认即它） |

成功返回 `InitializationResult`：

| 字段 | 说明 |
|---|---|
| `status` | 见下表 |
| `path` | 生成的题目文件绝对路径 |
| `associated` | v1 兼容字段：源码中的题目 URL、语言与提交区域已核验；不代表保存了 XML 关联或用例 |
| `implemented` | 恒为 `false`（只生成骨架，不实现解法） |
| `reason` | 失败/冲突时的补充说明 |

`status` 取值：

| status | 含义 | 调用方处理 |
|---|---|---|
| `created` | 骨架已创建且源码身份核验通过 | 直接开始写解法 |
| `already_exists` | 同一身份的骨架已存在 | 视为成功，继续写解法 |
| `partial` | 文件已写入或已有匹配题目，但工程、源码核验或打开编辑器未完成 | **检查目标文件**后决定是否重试；不要盲目覆盖 |
| `conflict` | 见 `reason`：`existing_file_not_touched`（同名文件身份不匹配）、`root_leetcode_marker_required`（项目无 `.leetcode` 标记）、`project_missing_or_ambiguous` | 人工介入检查 |

生成位置（固定约定）：

- Java：`code/java/src/main/java/leetcodecn/P0001_TwoSum.java`（Java 8 Maven 工程）
- Go：`code/go/leetcodecn/P0001_TwoSum/main.go`（Go module 工程）

同一时间只串行执行一个初始化（并发第二个返回 `409 {"error":"busy"}`）；单次超时 120 秒。服务端超时或底层异常一律返回 `409 {"error":"initialize_failed_or_cancelled_check_target"}`——超时/失败**不回滚已写入的文件**，必须先检查目标文件再决定下一步，不要自动重试创建。

### 错误码汇总

| HTTP | error | 触发 |
|---|---|---|
| 403 | `forbidden` | 源地址/Host/Origin/Authorization 校验失败 |
| 404 | `unsupported_operation` | 非 `/status` GET 或非 `/initialize-challenge` POST |
| 400 | `invalid_request` | JSON 解析失败或字段非法 |
| 400 | `unsupported_dojo_only_leetcodecn` | `dojo` 不是 `leetcodecn` |
| 409 | `project_not_open` | `project` 不在当前实例打开的标记项目中 |
| 409 | `busy` | 已有初始化在执行 |
| 409 | `initialize_failed_or_cancelled_check_target` | 初始化异常/取消/超时 |
| 413 | `request_too_large` | 请求体超过 4096 字节 |
| 415 | `json_required` | 缺 `Content-Type: application/json` |

## Node 客户端用法

`scripts/initialize_challenge.mjs` 封装了发现、鉴权与并发仲裁（多实例打开同一项目时拒绝猜测）：

```bash
# 查看哪些 IDE 实例打开了当前目录对应的项目
node scripts/initialize_challenge.mjs status --project /path/to/oh-my-algo

# 初始化题目
node scripts/initialize_challenge.mjs initialize \
  --project /path/to/oh-my-algo \
  --slug two-sum \
  --language java
```

`initialize` 成功（`created`/`already_exists`）退出码为 0，其余为 1。`--project` 缺省用当前目录。

作为库引用：

```js
import { initializeChallenge } from './scripts/initialize_challenge.mjs';
const result = await initializeChallenge('/path/to/oh-my-algo', 'two-sum', 'java');
// result.status: created | already_exists | partial | conflict
```

## 边界与注意事项

- 初始化只生成骨架、语言工程并核验源码身份；不保存项目题目状态，不写解法、不执行测试或提交。
- 不覆盖已有文件；软链接路径拒绝写入；目标必须在打开项目的约定目录内。
- 请求与初始化任务归属目标项目：关闭项目、卸载插件或超时会传播取消。
- 同一项目被多个 IDE 实例打开时，客户端会拒绝选择入口，需要先只保留一个实例。
- 诊断日志见 IDEA `idea.log` 中 `AlgoStack.Initialization` / `ChallengeAutomation` 相关条目。
