# 定制功能与 Challenge 自动初始化

返回[仓库首页](../README.md) · [开发指南](开发指南.md)

本仓库是个人维护的 LeetCode 插件源码。此前针对已安装 1.12.1-252 JAR 的本机补丁，不再作为新版本的实现方式；本版本通过 Kotlin 源码、Gradle 测试和插件 ZIP 交付。插件 ID 与提交区域契约保留；当前仅支持 LeetCodeCN。1.16.0 改为无数据库实现；下方本机安装记录仅描述当时版本，不代表当前实现。

## 题面纯文本

内置 Java／Go 模板使用以下字段（仅供源码维护，不提供用户模板编辑入口）：

```text
/*
https://leetcode.cn/problems/${challenge.slug}/
${challenge.descriptionText}
*/
${challenge.code}
```

纯文本转换保留比较符、`List<Node>`、已有换行与未知标签，`sup/sub` 转为 `^/_`，图片保留地址，注释终止符 `*/` 转为 `* /`。它不是通用 HTML 排版器或安全过滤器。Java／Go 内置模板自己包含可信题目 URL 和纯文本题面；生成器仅渲染模板并验证 URL 与唯一提交区域，不再附加重复头部或 language/version metadata，文件仅凭源码内容即可识别。

旧自定义模板不再读取；旧配置和已生成源码原样保留，不自动转换。

## 自动初始化的调用链

```text
Agent / CLI 确认题目、语言、项目和站点
    → 仅本机、带鉴权的初始化入口
    → 使用 Java／Go 固定生成约定
    → 获取题面与平台函数签名，渲染 Velocity 模板
    → CREATE_NEW 新建文件（已有匹配题目也继续检查工程）
    → 检查所选语言工程；默认布局缺失时 CREATE_NEW 创建 pom.xml / go.mod
    → 按文件内容核验题目身份，不保存 XML 关联
    → 刷新 VFS 并打开编辑器
```

初始化只准备骨架，不选择题目、不生成解法、不执行力扣测试或提交，也不自动弹出登录或设置对话框。Java、Go 均支持；仅支持 LeetCodeCN；省略站点默认中国站，显式国际站参数直接拒绝。公开题面不要求交互登录；平台拒绝访问或工程初始化失败时返回错误，而不是绕过权限。

自动化必须指定已打开且 root 存在 `.leetcode` 标记的项目。新题固定提供 Java／Go AnyVersion：中国站路径为 `$PROJECT_DIR$/code/java/src/main/java/leetcodecn` 和 `$PROJECT_DIR$/code/go/leetcodecn`。Java 文件及外层类名如 `P0001_TwoSum`，Go 使用同名子目录下的 `main.go`；数字题号至少四位，非数字题号沿用 slug 驼峰名称。路径与模板由插件内置约定决定，不读取旧项目配置；项目外路径和软链接父目录不受支持。已有其他语言题目的内容识别与提交契约保留，但不再提供新题生成入口。

手动打开题目保留交互登录和同名文件重命名对话框，不再引导配置；不会静默覆盖。Java 另存名称须为合法类名，确定最终文件名后，仅同步新骨架的外层 `public` 类声明（例如 `Retry.java` 对应 `public class Retry`），不替换提交区域中的平台类名、签名、字符串或注释，不改写已有文件。Go 另存不转换正文。这里的同步只发生在手动新建时，不是对已有题目文件的通用重命名重构；Agent 入口仍按固定路径返回 `created`、`already_exists` 或冲突结果，不弹出重命名对话框。

手动与 Agent 入口共用语言工程检查，但手动先检查工程再保存题目，Agent 在新建骨架后检查工程，失败按下述 `partial` 处理。

### 语言工程初始化

- 只初始化当前选择的 Java 或 Go，不因提供两种语言而预建另一种工程。默认 Java 工程根为 `code/java`，生成 Java 8 Maven 最小 `pom.xml`，不添加依赖或测试框架；源码仍由现有路径模板放入标准 `src/main/java`。Go 工程根为 `code/go`，使用稳定本地练习 module 名 `leetcode-practice`，默认每题一个独立 `package main` 目录。
- 本仓库此前没有练习工程 module 或 Go directive 约定。新 `go.mod` 的 `go` directive 查询本机 `go version`，只取 major.minor，不写死未来版本；查询设定 `GOTOOLCHAIN=local`、`GOWORK=off`，有超时，不下载工具链。不运行 `go mod init`、Maven 或依赖下载。无可用 Go 时提示安装 Go 或手动准备 `go.mod`；已有 module 不要求本机 Go。
- 从固定源码目录向上检查至项目根，遇到已有同语言 `pom.xml` / `go.mod` 就复用，不解析、升级或重写它，也不嵌套新 module。已有代码、工程及旧配置不覆盖。Java 路径遇到 Gradle 配置、Go 路径遇到 `go.work` 且未找到更近的描述文件时，要求用户明确建立目标工程，不猜多模块归属。
- 固定从站点目录推导 `code/java` / `code/go`，不提供自定义 source folder 或 Java 包名设置。工程检查仍拒绝猜测不明确的多模块归属。
- 两条入口对 Java/Go 都要求路径在项目内且父目录无软链接；描述文件必须是普通文件，不接受软链接或目录。进程内工程检查串行，写入使用 `CREATE_NEW`；并发已有文件只复用，不截断。不防御同用户恶意并发换目录，不自动修复其他进程留下的不完整描述文件。
- 已有匹配题目返回 `already_exists` 前仍检查并补齐工程。Agent 工程初始化失败时，已生成或原有骨架均保留，返回 `partial`，`reason` 包含提示；原有代码和旧 XML 不动。修复配置/Go 环境后可重试。文件、工程与编辑器不构成跨资源事务，可能留下空目录或不完整新文件，不自动回滚用户数据。

## 命令行

调用端为 [scripts/initialize_challenge.mjs](../scripts/initialize_challenge.mjs)，需要 Node.js 24。完整接口契约（鉴权、错误码、状态语义、安全边界）见[挑战初始化桥接接口](挑战初始化桥接接口.md)。以下命令从插件源码仓库执行，`--project` 指向实际打开的刷题项目，不一定是当前插件源码目录。

```bash
node scripts/initialize_challenge.mjs status --project /path/to/practice-project

node scripts/initialize_challenge.mjs initialize \
  --project /path/to/practice-project \
  --slug two-sum --language go

node scripts/initialize_challenge.mjs initialize \
  --project /path/to/practice-project \
  --slug reverse-string --language java --dojo leetcodecn
```

保持旧桥接的 v1 描述文件与默认三字段请求兼容，旧调用端可继续使用中国站；可选 `dojo` 字段仅接受 `leetcodecn`，国际站返回 `unsupported_dojo_only_leetcodecn`。这里兼容的是窄接口协议，不是旧补丁 class 或 JAR 哈希。

| 返回状态 | 含义 |
| --- | --- |
| `created` | 本次生成骨架并核对源码身份、打开编辑器；`implemented=false`，不表示算法完成或空骨架可编译 |
| `already_exists` | 已有文件内容识别出的站点、slug、语言/版本匹配，不修改源码或旧 XML；不判定已有实现是否完成 |
| `conflict` | 文件已存在但不匹配、陈旧映射、缺少启用标记或新建冲突，不覆盖已有内容 |
| `partial` | 骨架已创建或已有匹配题目，但语言工程、源码身份核验或打开编辑器未全部完成；保留原文件，`associated` 仅表示源码身份已核验，不代表持久化 |
| HTTP 错误 / 超时 / 取消 | 可能已发生部分写入，先检查目标文件和源码身份，不盲目重试或删除 |

文件系统、工程和编辑器不是一个跨资源事务；进程崩溃、项目关闭或磁盘故障仍可能留下部分结果。自动化入口不会自动退回外部写数据库的修复脚本。

## 安全与生命周期

- 仅监听 `127.0.0.1` 随机端口，每次启动生成新 token；校验 Host、Bearer token 和 Origin，拒绝来自网页的调用。
- 描述文件位于 `~/.local/state/algostack/bridge/<IDEA进程号>.json`；目录 0700、文件 0600，客户端校验所有者和权限，不打印 token。当前私有权限实现适用于 POSIX 环境；不支持时启动失败，不降级公开凭据。
- 只提供 `GET /status` 和 `POST /initialize-challenge`，限制请求体、slug、语言、站点和项目；status 只列出标记项目，初始化再次检查标记。无任意路径写入、代码执行或提交接口。
- 初始化在单个 IDE 实例内串行执行；同一项目被多个实例打开时，CLI 拒绝猜测目标。
- HTTP 服务属于应用生命周期；初始化任务属于目标项目 scope，关闭项目、卸载插件或超时会传播取消。释放串行锁前等待项目任务结束，但阻塞文件 I/O 可能不能立即中断。
- `CREATE_NEW` 防止同名文件覆盖；路径与软链接检查不是对同一用户恶意并发替换目录的完整防御。

## 标记项目启动与登录恢复

`AlgoStackStartupActivity` 首先检查项目状态和 root `.leetcode`，标记支持文件或目录。无标记直接返回，不读取业务设置或凭据，不显示插件版本通知、不启动桥接；编辑器 provider、图标/动作也受标记保护。添加或移除标记后重新打开项目，不提供运行时自动激活/卸载。

标记项目在后台调用既有应用级 `AuthService.ensureAuthenticated(dojo)`，不给 interactive 回调，因而不会主动打开 LoginDialog/浏览器。仅恢复中国站，只有有保存凭据时才请求校验；国际站凭据不读取、不删除，不依赖视图或语言设置。`CredentialsStore` 与 `AuthService` 都是应用级，同站点跨项目共享；没有另建项目级会话或平行恢复机制。

启动与视图沿用 `AuthenticationSession` 的 entry Mutex、generation/revision 和取消保护。应用生命周期内每站点最多完成一次自动静默尝试，包括缺失/失效/读取异常，避免多个项目/视图重复恢复；取消不计为完成，下一个项目可重试。显式 **Login** 仍可重新读取并验证保存凭据，恢复失败则进入原有 Cookie/浏览器手动登录流程。已有成功会话直接复用；网络临时故障不会在后台循环重试，需手动 Login 或重启 IDE。

恢复任务归属于启动项目，关闭项目会传播取消；不另建脱离项目的任务，也不改变原短凭据提交不可取消的规则。自动恢复不清除失效凭据、不改写项目模板或 queryCriteria。实际 PasswordSafe、代理、浏览器和 IDE 生命周期交互仍需真实 IDEA 验收。

## 当前配置与旧数据边界

新题使用内置目录、命名和模板，题面使用内置主题样式；不再提供设置页。旧 `.idea/CodeEpiphany/leetcodecn.xml` 的语言、路径、模板及 CSS 不再读取，不删除、改写或迁移旧文件。queryCriteria 完全不持久化。root `.leetcode` 仅作启用标记（文件或目录均可），无标记不启动插件业务或登录，不展示整个工具窗口。

底部固定 `Console` / `Problems`，只有选中可信题目源文件时才加 Description / Solutions；工具窗口 tab 切换不会清题目身份。Problems 首行使用“全部题目 / 公司题单”下拉框、关键词与搜索按钮；Enter 等价于点击搜索。输入草稿不发请求，筛选/翻页使用已提交关键词；范围切换保留各自字段与草稿，回首页并重置排序。

Java／Go AnyVersion 始终可供选择，不受旧语言列表影响。约定读取与模板渲染只操作内存，不提前创建目录或题目。

旧 Java/Go 文件通过全文件真实注释中的可信题目 URL 和唯一完整提交区域识别；URL 没有必须位于头部的隐式约束，支持 package/import 后、类或方法内部及行尾注释，但不采信字符串、Java 文本块或 Go raw string。识别与运行/提交共用区域定位，块注释中的示例不算边界，多个真实区域或跨题冲突拒绝；具体边界见[工程结构](工程结构.md#题目身份与旧文件)。1.17.0 起不使用 XML 身份兜底：无 URL 文件即使有关联也返回 conflict，XML 不能补充语言或版本；语言由扩展名唯一确定，版本固定 AnyVersion，不解析 language/version metadata。不读取旧 XML 的关联、标题或用例；不创建项目题目状态，不以旧 ID 查库。运行/提交按需异步获取后台 questionId 与默认用例，展示题号只用于标题和模板。没有可验证身份时返回 conflict，不猜测、更改或覆盖旧文件。

Notes/笔记、本地 Submissions 历史及相关 VFS 已删除；提交只在 Console 输出并链接到平台，Description 实时拉取，Solutions 平台题解保留。历史数据库不读取、不写入、不迁移、不删除；无需转换流程，旧历史数据由用户自行保留。开发验证只读核对旧题，不改写用户题解、配置、标记或安装目录。
