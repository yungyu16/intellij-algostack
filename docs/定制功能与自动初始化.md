# 定制功能与 Challenge 自动初始化

返回[仓库首页](../README.md) · [开发指南](开发指南.md)

本仓库是个人维护的 LeetCode 插件源码。此前针对已安装 1.12.1-252 JAR 的本机补丁，不再作为新版本的实现方式；本版本通过 Kotlin 源码、Gradle 测试和插件 ZIP 交付。插件 ID、两站配置标识、题目关联与数据库迁移保持兼容。

## 从旧补丁迁移了什么

| 能力 | 源码实现与边界 |
| --- | --- |
| JCEF 登录窗口依赖 | 当前工程和描述符已经声明 JCEF；新增回归确认依赖保留，不重复修改依赖或嵌入旧 class |
| 标题栏 Login 入口 | 当前 `DojoWindowFactory` 先注册选择监听，再更新内容，最后显式初始化标题栏；保留此实现 |
| 自动恢复登录 | 当前视图已有静默恢复；补充按站点协调、过期认证结果拒绝、保存凭据恢复异常后允许手动登录、短提交阶段一致性，以及浏览器瞬时失败的有界重试 |
| Challenge 自动初始化 | 原生 Kotlin 服务调用共享的模板、存储、关联与编辑器流程，不使用反射、ASM、Scala 或 jOOQ |
| 题面格式 | 新增 `${challenge.descriptionText}`，有限清理 HTML，包括保留 `font` 内的数字；原 `${challenge.description}` 仍返回 HTML，不覆盖已有自定义模板 |

旧安装包出现的连续 `Login canceled` 尚未确认根因，不能把本次源码迁移或离线测试写成旧问题已修复。新版本的登录与浏览器实际行为仍需客户端检查。

## 题面纯文本

自定义 Java／Go 模板可使用：

```text
/*
${challenge.descriptionText}
*/
${challenge.code}
```

纯文本转换保留比较符、`List<Node>`、已有换行与未知标签，`sup/sub` 转为 `^/_`，图片保留地址，注释终止符 `*/` 转为 `* /`。它不是通用 HTML 排版器或安全过滤器。原默认模板本来只生成代码包装，不引用题面，因此没有强行给所有默认模板加题面。

已有模板仍按原表达式运行；若已经使用修过 `font` 的替换链，可以继续用，也可自行改为新变量。插件不会静默改写用户模板。

## 自动初始化的调用链

```text
Agent / CLI 确认题目、语言、项目和站点
    → 仅本机、带鉴权的初始化入口
    → 读取对应站点的语言配置快照
    → 获取题面与平台函数签名，渲染 Velocity 模板
    → CREATE_NEW 新建文件
    → SQLite 事务保存题目 / 语言 / 解法记录
    → 更新 ChallengeSettings 内存关联
    → 刷新 VFS 并打开编辑器
```

初始化只准备骨架，不选择题目、不生成解法、不执行力扣测试或提交，也不自动弹出登录或设置对话框。Java、Go 均支持；默认 LeetCodeCN，可显式选择 LeetCode。公开题面不要求交互登录；平台拒绝访问或配置不足时返回错误，而不是绕过权限。

自动化必须指定已打开的项目，使用项目中配置的模板与保存路径，目标仍须在该项目内。不硬编码 oh-my-algo 的目录或题号格式，使用者可以定制模板；项目外路径和软链接父目录不受支持。其他语言仍可走原插件手动流程。

原手动打开题目继续保留配置引导、交互登录和同名文件重命名对话框；不会因为新增自动化而改为静默覆盖。

## 命令行

调用端为 [scripts/initialize_challenge.mjs](../scripts/initialize_challenge.mjs)，需要 Node.js 24。以下命令从插件源码仓库执行，`--project` 指向实际打开的刷题项目，不一定是当前插件源码目录。

```bash
node scripts/initialize_challenge.mjs status --project /path/to/practice-project

node scripts/initialize_challenge.mjs initialize \
  --project /path/to/practice-project \
  --slug two-sum --language go

node scripts/initialize_challenge.mjs initialize \
  --project /path/to/practice-project \
  --slug reverse-string --language java --dojo leetcode
```

保持旧桥接的 v1 描述文件与默认三字段请求兼容，旧调用端可继续使用中国站；新调用端支持可选 `dojo` 字段。这里兼容的是窄接口协议，不是旧补丁 class 或 JAR 哈希。

| 返回状态 | 含义 |
| --- | --- |
| `created` | 本次生成骨架并核对关联、打开编辑器；`implemented=false`，不表示算法完成或空骨架可编译 |
| `already_exists` | 已有文件的站点、语言、题目和解法关联有效，不修改源码、自定义用例或当前解法；不判定已有实现是否完成 |
| `conflict` | 文件已存在但不匹配、陈旧映射、配置缺失或新建冲突，不覆盖已有内容 |
| `partial` | 新文件已创建，但关联或打开编辑器未全部完成；保留文件，`associated` 表示关联是否已核验 |
| HTTP 错误 / 超时 / 取消 | 可能已发生部分写入，先检查目标文件与关联，不盲目重试或删除 |

文件系统、数据库、内存关联不是一个跨资源事务；进程崩溃、项目关闭或磁盘故障仍可能留下部分结果。自动化入口不会自动退回外部写数据库的修复脚本。

## 安全与生命周期

- 仅监听 `127.0.0.1` 随机端口，每次启动生成新 token；校验 Host、Bearer token 和 Origin，拒绝来自网页的调用。
- 描述文件位于 `~/.local/state/yy-leetcode/bridge/<IDEA进程号>.json`；目录 0700、文件 0600，客户端校验所有者和权限，不打印 token。当前私有权限实现适用于 POSIX 环境；不支持时启动失败，不降级公开凭据。
- 只提供 `GET /status` 和 `POST /initialize-challenge`，限制请求体、slug、语言、站点和项目；没有任意路径写入、代码执行或提交接口。
- 初始化在单个 IDE 实例内串行执行；同一项目被多个实例打开时，CLI 拒绝猜测目标。
- HTTP 服务属于应用生命周期；初始化任务属于目标项目 scope，关闭项目、卸载插件或超时会传播取消。释放串行锁前等待项目任务结束，但阻塞文件 I/O 可能不能立即中断。
- `CREATE_NEW` 防止同名文件覆盖；路径与软链接检查不是对同一用户恶意并发替换目录的完整防御。

离线测试覆盖：请求鉴权与两站/两语言分派、旧协议默认站点、参数与权限保护、并发拒绝、真实 Velocity 渲染、临时文件与 SQLite/内存关联、重复初始化不改用户代码及用例、部分失败与取消、认证竞争和题面格式。测试不使用真实账号，不执行平台提交。

认证协调保护服务内部恢复、验证和退出操作。普通业务 HTTP 响应自动更新 Cookie 的完整跨请求隔离，以及 PasswordSafe 在实际已写入后抛异常的情况，仍不具备跨组件事务保证，不把当前测试结果推广为所有认证场景都已覆盖。

安装前备份原插件目录与 `.idea/CodeEpiphany/`；全新 ZIP 替换整个旧插件目录，不能只替换主 JAR，否则会残留旧 Scala/jOOQ 运行库。安装需要完全退出 IDEA，重启后的日常初始化不需要关闭项目。

真实 IDEA 验收至少包含：保存会话恢复、手动 Cookie/浏览器登录、关闭登录窗口、两站隔离、多项目状态、Java/Go 首次生成、已有文件重复调用、编辑器入口、项目关闭与失败恢复。测试/提交入口是否出现与真正执行平台测试/提交分别确认，后者需用户授权。
